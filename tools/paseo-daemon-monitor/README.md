# 宿主机资源（Paseo 插件）

在 Paseo 侧栏底部常驻一行 CPU、内存、系统盘使用率，点击打开详情。空间足够时三等宽槽横贯整行，槽内图标、百分比和短条整体居中；宽度按实测行宽判定，拖窄时依次收起短条、收紧内边距/列距/图标与数字间距并用较小图标，仍不够就把图标叠在数字上方，三个图标和完整百分比在侧栏最小宽度仍保留。只有物理宽度连三列数字都放不下才退成纯数字行，从不截断。拉宽即逐级恢复，宿主报告紧凑布局时不显示短条。

## 设置

设置 → 插件 → 宿主机资源：

- **采样间隔**：2 秒（默认）、5 秒或 10 秒。CPU、内存与网速按此节拍采样，切换后同一条采样循环就地改节拍，不需要重载插件；磁盘仍约 30 秒刷新。
- **在底栏显示网速**：默认开启。关闭只影响侧栏底部一行的 ↓/↑；详情里的网速数值与曲线照常显示。

两项设置都保存在所选 daemon 的 host 作用域（`scope: "host"`），只影响该 daemon 这一份安装，所有连接它的客户端看到同一组值；其他主机的安装各管各的。

## 安装

在插件目录内直接安装，manifest 的 `id` 为 `daemon-monitor`，无需另设运行 ID：

```sh
paseo plugin install "$PWD"
```

源码更新后在同目录重载：

```sh
paseo plugin reload daemon-monitor
```

已有安装沿用其实际运行 ID。安装与重载都会写入该 daemon，须另行确认目标与授权。

## 取数口径

- 服务端插件代码运行在 daemon 进程旁，直接读 daemon 所在主机的数据，不需要路径、命令或凭据，也不向外传主机地址。
- 负载与开机时长：Linux 读 `/proc/loadavg` 与 `/proc/uptime`；macOS 用 `os.loadavg()`、`os.uptime()`；Windows 只有 `os.uptime()`，负载留 null，不伪造 0。
- CPU：Linux 取 `/proc/stat` 汇总行相邻两次计数，100% 代表全部逻辑核心满载；其他平台用 `os.cpus()` 同源计数。首次采样在同一请求内取两次，避免显示伪造的 0%。
- 内存：Linux 已用 = 总量 − `/proc/meminfo` `MemAvailable`；其他平台退到 `os.totalmem()`/`os.freemem()`，并在详情标明该平台没有 MemAvailable。
- 系统盘：`fs.statfs` 读系统根所在文件系统（`/`，Windows 为 `C:\`），已用按 `blocks - bfree`，可用按 `bavail`。
- 本地磁盘（Linux）：按 `/proc/mounts` 选块设备与 ZFS，排除网络、内存盘、squashfs/iso 等只读镜像，每个设备只取一次，逐个 `statfs`；百分比按 `df` 口径（保留空间既不算已用也不算可用）。枚举失败时退回单一系统根读数。
- 磁盘汇总：本地盘逐个去重后，把已用与可用分别求和再算百分比，`scope` 标明覆盖范围是「本地盘」还是仅「根盘」。根盘 `disk` 字段语义不变。
- 磁盘刷新：盘表与根盘读数同属 30 秒一次；两次刷新之间直接复用，不每 2 秒重打 statfs。刷新失败沿用上一次结果。
- 历史：约 3 分钟的有界内存序列（2 秒一个点），重载即清空。每点带 CPU、内存、上下行速率和磁盘汇总百分比；磁盘百分比是 30 秒阶梯值，两次刷新之间保持不变，不复制盘表。
- 停采恢复：无客户端 30 秒后停止采样。恢复时若距上次计数超过约 6 秒，本次 CPU 与网速按「空档」返回 null（历史里也是空热点），不把整段空闲平均当成当前值；下一拍恢复正常。曲线因此会出现合理空档，而不是被拉平的长平均。
- daemon 主进程（仅 Linux，可选）：进程 CPU、RSS、PID 读自插件父进程 `/proc`。启动时固定 ppid，IPC 断开或 ppid 变化即停止上报，绝不用插件子进程冒充。
- 网络（仅 Linux）：`/proc/net/dev` 累计字节的差值，不跑命令、不产生流量。跳过 loopback，以及 veth/docker/bridge 等已知虚拟接口，避免容器两端重复计数；接口集合变化或计数回退时该次速率记为未知，不是 0。
- 服务端默认每 2 秒采一次 CPU、内存与网速（可在设置改为 5 秒或 10 秒），磁盘每 30 秒单独刷新；采样由 daemon 内单个循环驱动，多个客户端与弹层共享同一份结果，不叠加读数，慢采样不与下一轮重叠。前端按同一节拍读取。

## 状态

正常时 footer 不带徽标；采样失败或主机断线时保留旧值并标注「旧样本／读取失败」。详情错误使用固定文案，不回显原始错误。

## 底栏布局

- 固定 44 DP 单行，按实测外框宽度 W 排布；桌面版右侧预留 `clamp(W − 368, 0, 112)` DP 的尾槽，因此 416 DP 出现采样时刻、480 DP 换成 ↓/↑ 时，前三组位置不移动、行高不变。
- 手机/紧凑版（宿主报告 compact）改用四分区：三组资源 + 右侧上下两行的 ↓/↑，短单位（`1.5K`/`2.4M`）。速率分组只在「开关打开且有有效样本（0 B/s 也算有效）」时占用空间，占用宽度取实测标签与字号预留中较大者；三组因此放不下完整百分比时整组先收起、空间归还给三列，紧凑版不再因布局类型禁掉短条。速率分组宽度只由字号决定（固定 40 DP 基准 × 系统字号 + 9 DP 分隔），不随当前数字或历史最大值变化；短速率按二进制单位取 `0B`–`9990G` 的有界写法。实测 40 DP 宽标签、1× 字号下，外框 ≥265 DP 就能保留三图标 + 完整百分比 + 双向网速；350/368/390/424 DP 各有 24/30/38/49 DP 的短条，1.3× 字号在同宽仍保留全部三项与网速。
- 三组等宽，组内自左向右为图标、不收缩的百分比、进度条；进度条吃掉该组剩余宽度，随侧栏拉宽而伸长，不再固定 22 DP。桌面版低于 248 DP 容器宽度先撤进度条；紧凑版只要有 ≥14 DP 余量就画，余量不够时同样先撤。
- 180 DP 级极窄时退成图标在数字上方的三列；只有物理宽度连三列数字都放不下才退成纯数字行，从不截断。
- 桌面版「在底栏显示网速」关闭或该主机没有网速数据时，尾槽回到采样时刻；紧凑版则整块尾部收起、时间只在详情里看。异常只用右上角小圆点，不推移三列。
- 系统字号放大时速率标签按字号预留；桌面在约 1.4× 以上退回采样时刻（无障碍标签仍读出双向速率），紧凑版预留随之加宽、真的放不下时收起速率组，详情都不受影响。
