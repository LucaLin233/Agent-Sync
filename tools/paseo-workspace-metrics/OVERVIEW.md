# 工作区用量

输入 `/metrics` 或从命令中心打开当前工作区的用量面板；已有对话的输入框工具条显示缓存按钮。累计开启时优先显示当前 workspace 的 Codex 累计缓存率（「缓存 98.2%」），累计关闭或不可用时显示最近样本（「最近 98.2%」）；加载中为「缓存 …」，无有效样本为「缓存 —」或「最近 —」。点击打开该对话所属工作区的同一面板。面板同时显示累计缓存率、累计覆盖、累计缓存读取/总输入，以及最近样本缓存率和最近覆盖，便于对照。打开会话详情后，可观测后续完整轮次的首个助手消息事件和整轮耗时。内置 Claude Code 提供输出计数的成功轮次还显示整轮输出速率。

适用 Paseo 0.16.0 及以上。在「设置 → 插件 → 工作区用量」齿轮里管理 host 设置：默认累计关闭、只显示最近样本；打开「累计统计」后默认按本机全部 workspace 各自汇总，高级设置可限制 workspace IDs 或填写 Codex home（留空自动发现）。开关或高级保存通过设置订阅立即刷新面板与按钮并清除旧累计缓存。`/metrics` 只在工作区输入框提供且不带参数。按钮跟随当前 host 的会话目录，已有对话会立即出现，归档或转入后台时移除，重连后按新目录重建。累计由 daemon 侧 RPC 读取 Codex rollouts：每个唯一 native 会话取最新一笔有效 `total_token_usage`，closed 计入，归档、后台、跨 workspace 和无法确认的会话排除，缺失不当零。关闭时服务端不访问累计数据，即使仍保留旧 allowlist；旧版 `allWorkspaces: true` 或非空 `workspaceIds` 继续按原含义启用。高级设置写入 `allWorkspaces: false` 和 `workspaceIds` 时只查询名单内 workspace；空名单报错。全部模式只放开 workspace 名单，服务端仍逐一校验每个会话的 workspace、状态与 Codex 标记。填写 host 设置 `codexHome` 时作为显式覆盖优先使用，须位于 daemon 用户家目录内，无效值返回明确错误而不回退；留空时先用 `CODEX_HOME`（管理员外部根，解析后仍须在配置根所在目录内），最后是 `~/.codex`。只进入固定的 `sessions/`、`archived_sessions/`，不跟随软链，不返回路径或正文。最近样本缓存率覆盖字段完整的 Codex 会话，包括可确认使用 Codex 的自定义 provider。服务商首字延迟和纯生成速度在缺少对应数据时留空。插件通过 Paseo 读取当前工作区的会话元数据和用量，实时观测只使用事件元数据。
