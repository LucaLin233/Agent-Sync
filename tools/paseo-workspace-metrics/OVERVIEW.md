# 工作区用量

输入 `/metrics` 或从命令中心打开当前工作区的用量面板；已有对话的输入框工具条显示用量按钮。按钮只有单行，协议不提供宽度，Paseo 0.17.4 的插件按钮整体 maxWidth 160 px、文字单行省略，所以可见文字只显示当前工作区累计 RPC 的缓存率，格式为「累计 98.9%」，标签与数值之间、数值与百分号之间都是普通空格，一位小数与百分号与面板一致。累计读取中为「累计 …」，累计关闭、不在本机累计名单、读取失败或本次返回无有效快照为「累计 —」，真实零为「累计 0.0%」，最长值为「累计 100.0%」，不拿最近样本、0 或过期范围的值补位。按钮不显示最近样本或 token 速率，最近完成轮和累计整轮速度只保留在面板「输出表现」。完整提示保留「打开工作区用量」「累计缓存」全称、一位小数与百分号，并写出累计缺值的实际原因（已关闭、名单外或读取失败），不再带最近样本字段。点击打开该对话所属工作区的同一面板。面板顶部以缓存为主：累计统计开启且可用时，青绿色的「累计缓存」用最大号数字显示累计缓存率并排在第一，靛蓝色的「最近样本缓存」用略小的同样式大号数字显示最近样本缓存率；两张卡有数据时各自附缓存读取、总输入和会话覆盖。累计关闭、读取失败或暂无有效累计快照时，最近样本缓存率移到第一张并以最大号显示可用读数，累计卡只写实际原因，不用空的大号数字压过它。下方「输出表现」沿用同一卡片样式，按上排同序排最近完成轮和累计整轮两卡，保留整轮输出速率、首 Token、整轮耗时、输出 token 和完成时间，以及累计整轮速率（所有有效完成轮输出 token 总和除以整轮耗时总和，含工具与等待，按耗时加权）、平均首 Token、完成轮、速率样本、首 Token 样本和会话数；标题与刷新按钮同一行，速率不用大号彩色标题。两排卡片共用同一表面，不用整块饱和填色或额外分组外框。颜色按浅/深主题取可读的实色与文字色。较新的完成轮即使缺少输出计数也仍是「最近完成」，不会退回更早的有速率轮；后续失败或取消不会抹掉上一次成功轮，回滚则清除它。累计是已发生的性能观测，不是计费总额：跨会话按轮次累加，回滚后重放的同一轮不重复计入（去重窗口为每个会话最近 64 个已完成轮），也不会把「输出表现」里的最近完成轮顶回，但已经观测到的历史轮仍保留在累计样本中。轮次结束时按钮会在既有常规频控外做少量有界补读，让晚落盘的 rollout 也能更新标签，不做周期轮询；补读期间同一工作区再有轮次结束，只恢复这条链的补读预算而不再另开计时器，成员或设置变化后在途旧结果作废。打开会话详情后，可观测后续完整轮次的「首个可见文本」和整轮耗时：只取轮开始到首个含非空白助手文本的 daemon 事件，空消息、工具和推理事件不算，也不是服务商 TTFT。内置 Claude Code 提供同轮输出计数时另显示本轮输出速率。累计统计开启时，Codex 会话还会单独显示「最近 Codex 完成轮」：只用该会话同一 rollout 的 task_started/task_complete 原生边界和累计输出 token 差，不与 Paseo 实时观测混合；带 error 的完成、中止、回滚不出该轮数据；输出基线只取上一完成轮可信的最终累计计数，计数缺失、回退、时间倒退或边界中断时速率留空。完成轮的边界耗时和 Codex 自报首 token 可独立显示（耗时可为 0），关闭或名单外时不会探测数据目录。若 Codex 自报 time_to_first_token_ms，另显示「Codex 首个模型 Token」，与 Paseo 首个可见文本分开。

适用 Paseo 0.16.0 及以上。正式使用本地目录来源，不从仓库安装或按仓库提交更新；源码变化后在原目录用运行 ID 执行 `paseo plugin reload`，不要用仓库 `update`。在「设置 → 插件 → 工作区用量」齿轮里管理 host 设置：默认累计关闭，面板只显示最近样本；打开「累计统计」后默认按本机全部 workspace 各自汇总，高级设置可限制 workspace IDs 或填写 Codex home（留空自动发现）。开关或高级保存通过设置订阅立即刷新面板与按钮并清除旧累计缓存。`/metrics` 只在工作区输入框提供且不带参数。按钮跟随当前 host 的会话目录，已有对话会立即出现，归档或转入后台时移除，重连后按新目录重建。累计由 daemon 侧 RPC 读取 Codex rollouts：每个唯一 native 会话取最新一笔有效 `total_token_usage`，closed 计入，归档、后台、跨 workspace 和无法确认的会话排除，缺失不当零。关闭时服务端不访问累计数据，即使仍保留旧 allowlist；旧版 `allWorkspaces: true` 或非空 `workspaceIds` 继续按原含义启用。高级设置写入 `allWorkspaces: false` 和 `workspaceIds` 时只查询名单内 workspace；空名单报错。全部模式只放开 workspace 名单，服务端仍逐一校验每个会话的 workspace、状态与 Codex 标记。填写 host 设置 `codexHome` 时作为显式覆盖优先使用，须位于 daemon 用户家目录内，无效值返回明确错误而不回退；留空时先用 `CODEX_HOME`（管理员外部根，解析后仍须在配置根所在目录内），最后是 `~/.codex`。只进入固定的 `sessions/`、`archived_sessions/`，不跟随软链，不返回路径或正文。最近样本缓存率覆盖字段完整的 Codex 会话，包括可确认使用 Codex 的自定义 provider。服务商首字延迟、纯生成速度和模型生成速率在缺少对应数据时留空。插件通过 Paseo 读取当前工作区的会话元数据和用量，实时观测只使用事件元数据。
