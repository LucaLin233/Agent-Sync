# 工作区用量

输入 `/metrics` 或从命令中心打开当前工作区的用量面板；已有对话的输入框工具条显示缓存按钮。累计开启时优先显示当前 workspace 的 Codex 累计缓存率（「缓存 98.2%」），累计关闭或不可用时显示最近样本（「最近 98.2%」）；加载中为「缓存 …」，无有效样本为「缓存 —」或「最近 —」。点击打开该对话所属工作区的同一面板。面板顶部两张卡片并排在窄屏自动换行：「最近完成」用大号数字显示该工作区最近一次成功完成轮的整轮输出速率，下面附同轮首 Token、整轮耗时和输出 token；「累计统计」显示累计整轮输出速率，即所有有效完成轮输出 token 总和除以整轮耗时总和（含工具与等待，按耗时加权），并附平均首 Token、缓存率、会话覆盖和样本数。下方保留累计缓存读取/总输入、最近样本缓存率和最近覆盖，便于对照。较新的完成轮即使缺少输出计数也仍是「最近完成」，不会退回更早的有速率轮；后续失败或取消不会抹掉上一次成功轮，回滚则清除它。累计是已发生的性能观测，不是计费总额：跨会话按轮次累加，回滚后重放的同一轮不重复计入（去重窗口为每个会话最近 64 个已完成轮），但已经观测到的历史轮仍保留在累计样本中。打开会话详情后，可观测后续完整轮次的「首个可见文本」和整轮耗时：只取轮开始到首个含非空白助手文本的 daemon 事件，空消息、工具和推理事件不算，也不是服务商 TTFT。内置 Claude Code 提供同轮输出计数时另显示本轮输出速率。累计统计开启时，Codex 会话还会单独显示「最近 Codex 完成轮」：只用该会话同一 rollout 的 task_started/task_complete 原生边界和累计输出 token 差，不与 Paseo 实时观测混合；带 error 的完成、中止、回滚不出该轮数据；输出基线只取上一完成轮可信的最终累计计数，计数缺失、回退、时间倒退或边界中断时速率留空。完成轮的边界耗时和 Codex 自报首 token 可独立显示（耗时可为 0），关闭或名单外时不会探测数据目录。若 Codex 自报 time_to_first_token_ms，另显示「Codex 首个模型 Token」，与 Paseo 首个可见文本分开。

适用 Paseo 0.16.0 及以上。在「设置 → 插件 → 工作区用量」齿轮里管理 host 设置：默认累计关闭、只显示最近样本；打开「累计统计」后默认按本机全部 workspace 各自汇总，高级设置可限制 workspace IDs 或填写 Codex home（留空自动发现）。开关或高级保存通过设置订阅立即刷新面板与按钮并清除旧累计缓存。`/metrics` 只在工作区输入框提供且不带参数。按钮跟随当前 host 的会话目录，已有对话会立即出现，归档或转入后台时移除，重连后按新目录重建。累计由 daemon 侧 RPC 读取 Codex rollouts：每个唯一 native 会话取最新一笔有效 `total_token_usage`，closed 计入，归档、后台、跨 workspace 和无法确认的会话排除，缺失不当零。关闭时服务端不访问累计数据，即使仍保留旧 allowlist；旧版 `allWorkspaces: true` 或非空 `workspaceIds` 继续按原含义启用。高级设置写入 `allWorkspaces: false` 和 `workspaceIds` 时只查询名单内 workspace；空名单报错。全部模式只放开 workspace 名单，服务端仍逐一校验每个会话的 workspace、状态与 Codex 标记。填写 host 设置 `codexHome` 时作为显式覆盖优先使用，须位于 daemon 用户家目录内，无效值返回明确错误而不回退；留空时先用 `CODEX_HOME`（管理员外部根，解析后仍须在配置根所在目录内），最后是 `~/.codex`。只进入固定的 `sessions/`、`archived_sessions/`，不跟随软链，不返回路径或正文。最近样本缓存率覆盖字段完整的 Codex 会话，包括可确认使用 Codex 的自定义 provider。服务商首字延迟、纯生成速度和模型生成速率在缺少对应数据时留空。插件通过 Paseo 读取当前工作区的会话元数据和用量，实时观测只使用事件元数据。
