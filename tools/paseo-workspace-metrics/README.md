# 工作区用量

适用 Paseo 0.16.0 及以上。在插件已启用的 daemon 主机上安装源码，安装无需构建。

正式安装采用 Git 来源，固定到已核对的已合并提交（完整 SHA）。

首次安装：

```sh
PLUGIN_ID=${PLUGIN_ID:?先按本次部署选定运行 ID}
REF=${REF:?填已核对的已合并提交完整 SHA}
paseo plugin install github:LucaLin233/Agent-Sync:tools/paseo-workspace-metrics --id "$PLUGIN_ID" --ref "$REF"
```

已有 Git 安装沿用现有运行 ID，更新到选定的已合并提交。Paseo 0.17.5 支持 `update --ref`，其他版本以目标 CLI 的 `paseo plugin update --help` 为准。

```sh
PLUGIN_ID=${PLUGIN_ID:?先确认现有安装的运行 ID}
REF=${REF:?填已核对的已合并提交完整 SHA}
paseo plugin update "$PLUGIN_ID" --ref "$REF"
```

本地开发可从源码目录安装。修改源码后用该安装的运行 ID 执行 `paseo plugin reload "$PLUGIN_ID"`，重载会读取该安装指向的目录。

所有安装、更新或重载前，确认目标 daemon、运行 ID 和本次写授权。

运行 ID 未知时用 `paseo --quiet plugin ls` 取 ID-only 输出；目标不支持该全局选项时说明缺口，不回退到完整记录。已知 ID 只核目标项：由可信本地进程调用目标的结构化入口，在工具输出前只投影运行 ID、允许的来源字段、已安装修订和运行状态，不输出目录或错误文本；失败只报失败，不转储 stderr，也不为补齐而读取完整记录。现有安装继续沿用读到的运行 ID，新部署按本次部署选定。安装来源不匹配时，先在授权范围内确定迁移方案，不直接按同一 ID 覆盖。

安装、更新或重载后按同一投影方式回读：由可信本地进程在工具输出前只投影运行 ID、允许的来源字段、已安装修订和运行状态；Git 安装或更新核对已安装修订等于选定提交，reload 核回执，设置另用目标适用的设置入口只取必要字段。没有可安全投影的入口时说明缺口，不以完整记录代替。该回读不联系远端，一致也不证明远端已有更新。

安装后在「设置 → 插件 → 工作区用量」的齿轮打开设置：默认累计统计关闭，面板只显示最近样本；打开「累计统计」后默认按本机全部 workspace 各自汇总，可在「高级设置」里改为只查询指定 workspace ID，并可选填 Codex home（留空自动发现）。保存使用 host 设置的 revision，其他客户端和已打开的面板、输入框按钮会随设置订阅刷新并清除旧累计缓存，不需要重载插件。

在工作区输入框输入 `/metrics`（无参数），或从命令中心搜索「打开工作区用量」。已有对话的输入框工具条会显示用量按钮。按钮只用一行，协议不提供宽度，Paseo 0.17.4 的插件按钮整体 maxWidth 160 px、文字单行省略；因此可见文字只显示当前工作区累计 RPC 的缓存率，格式为「98.9%」，沿用面板的一位小数和百分号。累计读取中为「…」，累计关闭、不在本机累计名单、读取失败或该次返回无有效快照为「—」；真实零写「0.0%」，最长值写「100.0%」。最近样本不在按钮上显示，也不会拿来填补累计槽。按钮不显示任何 token 速率；「最近完成轮」和「累计整轮」速率只保留在面板「输出表现」里。完整按钮标题（悬停提示和无障碍名称）保留「打开工作区用量」「累计缓存」全称、一位小数和百分号，并写出累计缺值的实际原因，例如「打开工作区用量 · 累计缓存 —（累计统计已关闭）」或「打开工作区用量 · 累计缓存 —（累计读取失败：…）」；标题也不再带最近样本字段。按钮随当前 host 的会话目录增删，归档、后台或没有 workspace 的会话不注册，重连后按新快照重建并限制同一会话只保留一个。`/metrics` 在 Paseo 0.17.1 不与内建客户端命令（`exit`、`quit`、`q`、`clear`、`new`）冲突。

面板顶部按缓存优先排列两张缓存卡，宽屏并排，紧凑宽度可靠堆叠：累计统计开启且读得有效缓存率时，左侧青绿色「累计缓存」以最大号数字显示累计缓存率，右侧靛蓝色「最近样本缓存」以略小的同样式大号数字显示最近样本缓存率。累计关闭、范围外、加载中、读取失败或尚无有效累计快照时，不保留空的大号累计数字，「最近样本缓存」移到第一张并以最大号显示当前读到的可用缓存率；原「累计缓存」卡保留实际原因（已关闭、名单外、读取失败、暂无快照或正在读取）。两张缓存卡有数据时各自附缓存读取、总输入和会话覆盖的完整计数，累计卡另附缺失/排除说明；不再单列重复的「缓存摘要」。下方「输出表现」沿用同一卡片样式，按上排同序排「最近完成轮」和「累计整轮」两卡：前者保留整轮输出速率、首 Token、整轮耗时、输出 token 和完成时间，后者保留按整轮耗时加权的累计速率、平均首 Token、完成轮、速率样本、首 Token 样本和会话数；标题与刷新按钮保持同一行。速率在这里只用普通次要数字，不用大号彩色标题；累计速率按整轮耗时加权并含工具与等待。两排卡片共用同一表面，不用整块饱和填色或额外分组外框。面板与提示均保留一位小数或完整计数，输入框按钮沿用同样的一位小数和百分号；配色按浅色/深色主题分别取可读的实色与文字色，不写死只适合暗色的颜色。会话行把标题、缓存率徽标和详情入口放在一行，provider/模型/状态另起一行；各会话详情、空态、刷新和失败说明保留。累计由 daemon 侧 RPC 读取 Codex rollouts；最近样本仍由 Paseo 的 `lastUsage` 读取。输入框按钮与面板共用累计口径、一位小数格式和同一个累计读数槽：面板打开或刷新取得有效结果时，按钮与标题同步更新；同一 workspace 的重叠读取不会互相作废有效回包，迟到的旧回包也不能顶掉已采纳的新结果。两者采样时点仍可能不同。

| 指标 | 口径 |
| --- | --- |
| 累计缓存率 | 服务端按当前 workspace 的可见 Codex 会话校验 `workspaceId`、归档状态、provider 或 `persistence.metadata.provider = "codex"` 标记，以及 UUID 形式的 `nativeHandle`。每个唯一 native 会话只取最新一笔有效 `payload.info.total_token_usage`，汇总 `cached_input_tokens / input_tokens`。closed 会话计入；归档、后台、跨 workspace 或无法确认的会话排除。缺失、无效或不完整快照不计为 0。 |
| 累计覆盖 | `covered / eligible`：有有效累计快照的唯一 native 会话数 / 当前 workspace 可确认的 Codex 唯一 native 会话数。另有缺失和排除会话数用于说明失败原因。 |
| 最近样本缓存率 | 每个可确认使用 Codex 的会话取当前 `lastUsage` 一次。汇总缓存读取后除以汇总输入，Codex 输入已包含缓存读取。缺字段或分母无效时排除该样本，明确上报零缓存命中会纳入计算。覆盖分母是当前面板可见会话数。 |
| 输入框用量按钮 | 可见文字固定为「98.9%」：只使用同一累计 RPC 返回的缓存率，口径与「累计缓存率」相同，格式与面板一致的一位小数和百分号。累计读取中显示「…」，累计关闭、不在本机累计名单、读取失败，或该次返回无有效快照时显示「—」；真实零显示「0.0%」，最长值为「100.0%」。绝不把最近样本、凭空的 0 或过期范围的值填进累计槽。按钮不显示最近样本或 token 速率；面板「输出表现」保留最近完成轮与累计整轮的速度指标。完整按钮标题保留「打开工作区用量」和「累计缓存」全称、一位小数与百分号，累计缺值时写出实际原因（已关闭、名单外或读取失败），不再带最近样本字段。协议把按钮限制为单行、整体 maxWidth 160 px，所在行还可能继续压缩；按该样式估算文字区约 112 px，本格式最长「100.0%」按六枚约 6.7 px 数字/符号粗估约 37 px，但这是边界估算，不是真实客户端渲染结果。会话目录只驱动有界补读：普通更新沿用每 workspace 10 秒的常规频控，轮次从运行中转为终态（或终态下 `updatedAt` 前进）后另做最多 3 次、每次间隔 1.2 秒的 `refresh` 补读，覆盖 rollout 晚于目录事件落盘的情况；无新目录事件也会更新，不做周期轮询。同一 workspace 在补读链尚未结束时又有新终态，只刷新这条现有链的 3 次预算，复用同一个在途计时器；只有有效、范围内的可见会话会触发。同一 workspace 的成员集合变化或设置代际变化会作废旧结果；同一 workspace 的重叠补读串行化，有请求在途时新需求合并为一次后续读取。按钮与面板共用一个累计读数槽：任一侧取得后端校验的有效结果（含真实 0%）即更新按钮与标题；每次请求带单调签号，签号更旧的迟到回包不会覆盖已采纳的更晚结果，签号更新的回包即使在旧结果之后到达仍会替换显示。按钮自己的设置流尚未收到首个事件时，面板已校验的当前 workspace 读数可直接呈现；明确关闭、名单外或设置代际变化仍按既有原因清除。成员集合变化触发重读期间，仍有可见成员且上回读到过有效百分比时，按钮保留该值（含真实 0%）直到匹配的新回包替换；首次加载、已完成但无有效快照、读取失败，或全部可见成员离场，按原逻辑清除，显示各自既定的加载或缺值状态。 |
| 最近完成 | 跨当前 workspace 已校验的 Codex 会话，按完成事件时间选择最近一次成功完成轮；速率、首 Token、整轮耗时和输出 token 取自同一轮：首 Token 用该轮 `time_to_first_token_ms`，整轮耗时用 `task_started` 到 `task_complete`，整轮输出速率用该轮输出差除以整轮耗时。面板中这些速率只作「输出表现」两卡里的次要数字。较新的轮次即使没有输出计数或耗时也保留为最近完成，不会回退去挑更早的有速率轮。 |
| 累计整轮输出速率 | 该 workspace 已观测到的成功完成轮中，输出 token 总和除以整轮耗时总和（含工具与等待），即按每轮耗时加权，不是各轮速率的简单平均。只累加同时有输出差和正向耗时的轮次，分母独立计数。 |
| 平均首 Token | 有 `time_to_first_token_ms` 的成功完成轮之和除以这些轮数，分母与速率样本分开；缺值不按 0 计入。 |
| 累计边界 | 累计是「已发生的性能观测」，不是计费总额，也不代表这些轮从未被回滚：每个唯一 native 会话只统计在 rollout 中实际读到过的成功完成轮，回滚后重放的同一 `turn_id` 不重复计入；去重只覆盖该会话最近 64 个已完成 `turn_id`，更早的重放不在窗口内。回滚本身会清除「输出表现」里的最近完成轮，但已观测到的历史轮仍留在累计样本里；回滚后重放的同一轮仍会按文件事件顺序刷新该会话的详情终态，累计只计一次，也不会因此把最近完成轮顶回。每会话的最近成功轮按完成时间取最大值，详情仍按文件事件顺序。设置、范围或数据根变化会清空并重读，不复用旧口径。 |
| Paseo 首个可见文本 | 打开会话详情后，仅用同一轮的 daemon 时间戳，取 `turn_started` 到首个含非空白助手文本的 `assistant_message` 事件；空或纯空白消息、工具和推理事件不算。它可能出现在工具操作之后，也不是服务商 TTFT。 |
| Paseo 整轮耗时与本轮输出速率 | 耗时从轮开始到终态。内置 Claude Code 成功轮次另用该轮主循环输出 token 除以整轮耗时，包含工具与等待。计数缺失、轮次不完整或断线时段留空。 |
| 最近 Codex 完成轮 | 仅累计统计开启且能确认 Codex（含 CCHP/GDR 等别名标记）时显示。只用该会话同一 rollout 内同一 native `turn_id` 的 `task_started`/`task_complete` 边界，以及两边界之间最后一笔累计 `total_token_usage.output_tokens` 相对 `task_started` 时累计值的差；耗时同样取这两个原生边界。它与上方 Paseo 实时观测独立展示，不按客户端时间窗切分。起点基线只取上一完成轮可信的最终累计输出值；该轮缺少最终计数、边界中断或中途被新的开始取代时，下一轮基线作废。轮内每个计数都要时间前进、不低于起点基线且不倒退；任一回退或时间倒退都使该轮速率留空。`task_complete` 带非空 `error` 时不出该轮数据并清空基线；`turn_aborted` 清空详情终态但不改变「输出表现」里的最近完成轮；`thread_rolled_back` 清除该轮并同时清除最近完成轮。完成轮有原生边界时，耗时可独立显示；`time_to_first_token_ms` 可独立显示；两者都不依赖输出计数。「输出表现」里的最近完成轮只取最近成功轮，后续失败或取消不会让它退回更早的轮次。 |
| Codex 首个模型 Token | 同一完成轮 `task_complete.time_to_first_token_ms` 有非负整数时显示，即使该轮缺少有效输出基线也照常显示。它是 Codex 自报的模型首 token 时间，与 Paseo 首个可见文本口径不同，也不冒充服务商 TTFT。 |

## 累计数据来源与边界

Codex 数据根：填写插件 host 设置 `codexHome` 时作为显式覆盖优先使用，必须解析到 daemon 用户家目录内；不存在、不是绝对路径或越界时返回明确错误，不会静默回退到其他根。留空时先用 daemon 进程的 `CODEX_HOME`（作为管理员配置的外部根，规范化并解析软链后必须仍位于其配置根所在目录内），最后才是 `~/.codex`。workspace 允许列表由 Paseo 的 host 设置提供，不写入发布源码。只会进入数据根下固定的 `sessions/` 和 `archived_sessions/`，不跟随软链，不允许解析结果逃出数据根。

累计统计默认关闭，关闭时服务端不访问任何 cumulative 数据，即使设置里还留有旧 allowlist。显式打开后默认覆盖本机全部 workspace；高级设置可写入 `allWorkspaces: false` 和 `workspaceIds` 限制名单，空名单会报错而不会放开。旧版只含 `allWorkspaces: true` 或非空 `workspaceIds` 的设置继续按原含义启用；新设置用可选 `cumulativeEnabled` 统一表达开关。服务端仍逐一校验每个会话的 workspace、归档、后台、Codex 标记与 UUID，范围读取失败时前端不会声称该 workspace 不在白名单。两个 RPC 都用同一份设置快照确定范围，关闭、名单外或会话校验不通过时不会解析或探测任何数据目录；通过后才解析同一快照配置的根，并在 `agent.refresh()` 之后、读文件前和返回前核对设置 revision。配置已变就丢弃结果，不会在旧授权下读新目录。聚合缓存键包含设置 revision、解析后的可用根、请求会话、有效会话与不可用数量，换根或成员变化不会复用旧结果。手动刷新绕过短聚合缓存与路径负缓存；每次观测到轮次后最多三次、每次 1.2 秒由查询自身重读，覆盖终态先于落盘的情况，卸载或观测变化时撤销。服务端只接受 workspace ID 和会话 ID，不接受客户端路径；每个会话都用 Paseo 的 exact agent ref 刷新后校验，拒绝跨 workspace、归档、后台、非 Codex 或 `nativeHandle` 不是 UUID 的成员。rollout 文件名必须与该 UUID 精确匹配。每个 UUID 的日期目录或归档精确匹配结果最多缓存 30 秒；文件按 `dev/ino/size/mtime/ctime` 校验身份并只从上次偏移继续读取，不建立全局会话索引。单文件上限 256 MiB，单目录条目上限 5,000。

JSONL 每行先看前 240 字节是否含 `event_msg` 标记，再看是否含 `token_count` 或轮次事件，命中后才解析并复核 `type` 和 `payload.type`。累计只读取 `payload.info.total_token_usage` 的 `input_tokens`、`cached_input_tokens` 与 `output_tokens`，要求非负安全整数且缓存不超过输入；同一会话较新的累计快照覆盖旧值，不累加。轮次边界只投影 `turn_id`、`error` 是否存在、`time_to_first_token_ms` 和行时间戳；读取使用结构级白名单扫描，先按顶层真实事件 `type` 识别对象，再跳过所有非白名单字符串和嵌套正文，`task_complete` 的助手正文与嵌套错误内容不反序列化、不保留，也不会进入客户端状态。坏缓存快照保留上一笔有效输入/缓存样本，不影响轮次判断；有首 token 但边界耗时为 0 时仍显示首 token。时间戳或输出计数缺失只影响轮次级指标，累计输入/缓存仍按原口径解析，读取层分别返回缓存样本和完成轮。RPC 只返回计数、覆盖和错误说明，不返回会话路径、native 会话 ID、turn ID 或消息内容。

详情中的「上报」计数沿用 provider 的口径。输入框按钮的会话目录订阅只取公开 ID、`workspaceId`、归档与后台标志以及 `status`/`updatedAt` 这两个公开状态字段，不读用量，也不保留完整快照；面板按需刷新会话时另取 `lastUsage` 用量数值和 `persistence.metadata.provider` 这一个非秘密 Codex 标记，只为该面板算出最近样本，不做按钮汇总。累计接口在 daemon 侧读取授权的 Codex rollout 计数，不读取或传出正文。插件停止或重载时撤销按钮、定时器和面板注册。

会话行保留原始 provider ID。别名会话的 `persistence.metadata.provider` 明确为 `codex` 时，以 Codex 口径计算缓存率。插件在持久会话元数据中只读取这个标志。缺少该标志的别名会话仍可查看最近用量和 Paseo 事件耗时。[Paseo v0.17.1 provider 包装层](https://github.com/getpaseo/paseo/blob/v0.17.1/packages/server/src/server/agent/provider-registry.ts#L326)
