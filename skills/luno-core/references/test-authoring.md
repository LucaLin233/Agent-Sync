# 测试的编写与维护

本资源管 `tests/` 里用例的新增、修改和退休：什么能进常跑、单个用例的成本上限、断言和夹具要求，以及登记。运行方式见 `README.md` 的测试一节；必跑集合只按 `tests/run-tests.sh` 头部的〈变更路径→必跑套件〉取命中项的并集，本资源不另订跑集。审查侧的判据（测行为而不是实现、变异是否有效）在 `luno-core/references/code-review.md`。本资源不授予写入、部署或平台权限。

## 跑集与报账

- **按变更路径取最小跑集**：按〈变更路径→必跑套件〉取命中项的并集并完整执行，不自行增减；不默认加跑没命中的整套回归，也不只跑被改的那一个文件而省掉表里要求的回归。这里只约束测试选集，变化对象的授权、备份和落端回读仍按 `references/sync.md`〔分支 sync-workflow〕，不要求每次同步正文都访问未变化的端或跑 MCP 巡检。
- **按实际执行的集合报耗时**：报实际运行的入口、各集合的耗时和总耗时，额外跑过的 `group`/`case` 也算进去，不能只报 `full`；按需的平台巡检耗时单列。
- 用例增删后，在 PR 里报 `tests/` 的体积净差和实跑集合的耗时变化。

## 准入与预算

- **新用例默认不进常跑**，放进 `group` 或 `case`。要进 `full`，须在文件头和 PR 里写明为什么每批都必须跑；是否成立由当批的发布者裁定，独立审查只给意见。
- **优先并入同族文件**，不新开文件；确需新开的，在 PR 里说明为什么不能并入。新增测试文件或分组，要同时登记 `tests/run-tests.sh` 的用例表和 `tests/test_paths.py` 的路径表，没登记的不会被跑到（结构测试会检查这一点）。
- **预算**是默认的设计预算，不是已证明的通用上限：单个入口 ≤ 10 s，单个文件 ≤ 20 KB（20 480 B，UTF-8 原始字节）。超限要由发布者裁定，并记录环境、实测、理由和降级路径；超过 10 s 的入口要在文件头写明为什么必须这么重、能否降级。历史上的大文件不要求整体压回预算，但改动要报增量，不能以它为先例新增同类。
- **提速是单独的改动**：要同时给出等价性证明（退出码和 stdout 断言不变；改为进程内执行入口时，每个入口脚本至少保留一个真实子进程用例守住进程边界）和前后耗时对比，不能删判据换速度。并行执行在 iSH 上的收益没有验证过，不作推荐手段。

## 写法

- 断言精确的错误类别，不用「包含某个子串」代替；一个用例只证明一件事。
- **负控不能空转**：去掉故障注入后用例必须变红；只看到「注入后变红」不算证明。
- **夹具隔离**：每个用例开始时清空共享和全局的夹具，不复用上一个用例的残留；不在空集合上写恒真的断言（`all(...)` 之类）。
- **不硬编码计数和清单**（日期文件数、技能数、平台 id 数、登记清单的副本等），从真源现读现算；夹具里抄一份登记清单，迟早会随批次过期。
- **不钉文档措辞**：测试不断言规则正文的逐字句子。确需检查文档的（如读取模板的声明面），只检查结构或契约，并在测试里注明它检查哪份文档的哪项契约。
- 离线、确定性：不依赖网络、时间、随机数和外部状态；同环境验收才算数。
- 只写「当前状态契约」和「定向回归」两类用例，不新增历史快照或冻结链；需要证明历史形态时，用当轮的资产留存，不进仓库。
- 产物和用例命名避免 `luno-<slug>` 的形态，以免和受管技能混淆。

## 退休

- 实现或对象退休时，它的用例在同一批退休，不留空转的用例；在 PR 里写明删了什么、判据迁到了哪里（确实无需迁移就写明理由）。
- 撤掉脚本步骤或删除脚本后，逐个跑受影响的 `group`/`case`：不在常跑集里的用例会静默损坏。

## 登记

新增或退休本类按需资源时，同步 `README.md` 的资源说明、`skills/luno-core/references/sync.md`〔分支 sync〕 的触发句、`tools/rule-claims.tsv` 的加载边和资源边，以及 `tools/sync-targets.json` 的资源清单。只改用例内容、不改变入口或常跑集时，不需要改技能正文。
