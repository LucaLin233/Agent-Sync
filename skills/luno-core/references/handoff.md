# 交接与恢复

只用于专业任务的交接、阶段恢复和相关规划判断。

**什么时候写交接**：到达阶段边界（方案待实操、批量收尾、审查或验收出结论、里程碑、切换话题），并且后续需要恢复时，写交接。有写入授权时，把目标、决策、待办和关键路径写进跨会话持久目录里的 `HANDOFF.md`，并给出路径；已有的 spec、issue、diff 等产物只给稳定指针和必要摘要，必要的恢复信息仍然内联，不复制全文。没有写入授权时，直接在答复里交接；不要只为提醒而新建文件。

**什么时候建议压缩或开新会话**：直接对话中，同时满足以下条件时，才建议压缩上下文或开新会话，并给出恢复要点：

- 可以安全收束：交付已完成或切换话题，或者阶段已收口、没有在途操作和待决授权；
- 可见上下文已经完成至少两个实质阶段（子步骤不算）；
- 后续批次或轮次明确需要沿用本轮的结论、版本、证据或待办；
- 用户没有拒绝过，且本工作单元还没提醒过。

只提醒一次，不等答复、不追问、不预报剩余容量，也不自动执行。被派发的子代理只交接自己的部分，不判断父会话的负载。

**恢复时**：看到卸载占位符、压缩摘要或内容缺失，当轮用一句话告知内容被裁剪或压缩、细节可能缺失，以及回读路径。从压缩或新会话恢复时，先核对项目、任务标识、版本和授权是否仍有效；在授权内读已知的 `HANDOFF.md`（没有就读已有的交接内容），恢复目标、授权、验收缺口、证据和下一步，并明确列出缺失项。交接文件缺失不授予写入或全局搜索的权限。
