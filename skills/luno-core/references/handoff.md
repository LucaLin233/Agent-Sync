# 交接与恢复

**交接内容与落点**：沿用 `references/execution.md`〔分支 execution〕〈执行闭环〉的公共交付字段，只保留一份当前状态，另载目标与验收、原授权范围及下一步；既有 spec、issue、diff 和原证只给稳定指针及必要摘要，不复制全部历史。有写入授权时写入已授权的跨会话 `HANDOFF.md` 并给路径；无写入授权时内联，不为提醒另建文件。

**有界连续推进**：不因任务长、角色切换、开 PR、普通回包或进入合并、部署、回读而暂停。批次沿用用户安排或已定的可独立验收工作单元，不为压缩另拆短任务。每批全部完成（含获准的发布及回读）后、下一批开始前只停一次：停止新操作和派单，核清在途，完成写入回读及获准临时物清理，先写交接，再提示用户查看输入框用量，在约30%（约300K）时手动压缩；该数值只是用户操作参考，不是助手可估算的余量或平台硬限。待压缩后恢复或用户明确跳过当前节点再继续；同一节点不重复提醒。用户可随时说「停」，收到即停止新操作，核清在途并安全收尾。范围扩大只停受影响部分，不中止仍可完成的授权内工作。

**容量与缺证停止**：收到 App 实际容量提示、发生压缩，关键原文、授权或版本无法可靠定位，达到调用时限或审查预算，或必须由用户取舍时，停止依赖步骤，核清在途，完成上述最小安全收尾并交接；缺口补齐后才恢复。不猜测 token 余量，不自动执行压缩，不改 App 自动压缩设置；自动压缩只作平台兜底。被派发子代理只交接自身部分，不判断父会话负载。没有下一批且不需恢复时，不为已完成任务另设暂停点。

**恢复时**：看到卸载占位符、压缩摘要或内容缺失，当轮说明细节可能缺失和已知回读路径。在原授权内回读已知交接与必要原件，核项目、任务、版本、真实执行状态及原授权是否仍适用，恢复验收缺口和下一步；不能用摘要代替必要原文。无法可靠定位的只停依赖部分；交接缺失不授予写入、全局搜索或扩大材料范围的权限。
