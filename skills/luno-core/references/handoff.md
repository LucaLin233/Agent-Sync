# 交接与恢复

只用于专业任务的交接、阶段恢复和相关规划判断。

**什么时候写交接**：到达阶段边界（方案待实操、批量收尾、审查或验收出结论、里程碑、切换话题），并且后续需要恢复时，写交接。有写入授权时，把目标、决策、待办和关键路径写进跨会话持久目录里的 `HANDOFF.md`，并给出路径；已有的 spec、issue、diff 等产物只给稳定指针和必要摘要，必要的恢复信息仍然内联，不复制全文。没有写入授权时，直接在答复里交接；不要只为提醒而新建文件。

**多阶段长任务的暂停节点**：取证与方案确定后、实施前；实现、验证及所需的独立审查完成后、合并或部署前；整批部署回读完成后、下一批前。到点先停止启动新操作和新派单，做完最小安全收尾（写入回读、临时产物清理、持久交接），核清在途操作，然后写交接并明确提示压缩，结束当前操作，等压缩后继续。阶段内范围扩大或必须重做方案时，安全收尾后提前停，避免阶段无限扩张；普通短任务不强拆阶段。用户可明确跳过当前节点，跳过只作用于该节点，不取消之后的节点。这些节点按工作事件触发，不猜实时 token 余量，也不是容量阈值或平台硬限制。

**什么时候建议压缩或开新会话**：直接对话中的较长任务在交付完成、切换话题或阶段收口后，若没有在途操作和待决授权，且后续需要沿用当前结论、版本、证据或待办，就建议压缩上下文或开新会话，并给出恢复要点。压缩提醒按节点计，一次提醒不覆盖本会话的其他节点；同一节点用户已拒绝或已跳过时不再重复该节点。

提醒不等答复、不追问、不预报剩余容量，也不自动执行。被派发的子代理只交接自己的部分，不判断父会话的负载。

**恢复时**：看到卸载占位符、压缩摘要或内容缺失，当轮用一句话告知内容被裁剪或压缩、细节可能缺失，以及回读路径。从压缩或新会话恢复时，先核对项目、任务标识、版本和授权是否仍有效；在授权内读已知的 `HANDOFF.md`（没有就读已有的交接内容），恢复目标、授权、验收缺口、证据和下一步，并明确列出缺失项。交接文件缺失不授予写入或全局搜索的权限。
