# LUNO｜审查与独立验收

## 范围与授权

审查不授予修改权，也不撤销已授权的修复。

需要独立放行时，除用户或领域明确要求额外独立阶段外，只设一次内容审查：可先做隔离候选的，审完成必要自验的实际最终差分；不能先做候选的，在首次实际高风险动作前审确定方案。内容审查可与 PR 的 CI 并行；本地已有有效独立审查的直接继承，本地测试或 CI 通过不冒充内容审查。合并或部署前仍须必要校验、独立审查和负责人核验均通过。同一已审内容、范围及关键证据未变时，PR、合并、部署只核相应版本、CI、现场前态和执行后回读，不新增全量内容审查；实际偏离或版本、证据、范围变化影响原结论时，只定向复核受影响部分。

## 审查执行

- **资格**：独立判断者必须未参与被审版本的实质制稿或实现、身份可核、已加载本规则；LUNO、LENS、FORGE 均按同一标准判断，角色名不授予资格，合格的当前主体可自办。需求、验收定义和授权协调本身不算实质制稿。审查意见须给明确最小 patch 或必要完整替换，不因此一概视为作者；但实际承担被审内容的实质编写，或重写其设计、边界的，即成为该版本作者，不能独立放行自己的版本。是否实质参与按实际贡献判断，不以建议或审查名义规避；自验、匿名或通用兜底不代替所需独立判断。不在本流程里改通道配置。
- **材料**：取得确定的对象和版本、需求、范围、原文或 diff、未关闭项和自验证据，按 `luno-core/references/review.md`〔分支 delegation〕 核对契约。证据可能过时或不全，疑点只在授权的对象和环境内低负载补证并记来源；派单指定「仅所给材料」时不补证。越界确认或缺依赖只停相关项。
- **单元与预算**：同一对象（路径或 ID 加版本）一次一个单元；文件集互不重叠且可分开验收的才并行。同版本出现新证据、范围变化或结论疑点时，可以定向复审并说明原因。整条链最多 3 轮有效内容审查（首次 1 轮加最多 2 次复审）；确认没有交付任何内容审查产出的通道失败不计轮次，仍受下条的一次通道重试和调用时限约束；身份不可核或交付状态不明仍须暂停。审查轮次不因暂停、睡眠、跨天、改名、换版本或换会话重置；负责人传入链 ID 及已用和剩余审查轮次，授权延续、恢复和调用时限按 delegation〈预算与停止〉。同一故障反复未闭合时先回到定位和修复验证，不刷绿或用放行代替修复。需要新授权或取舍，或相邻两轮同一问题的状态、覆盖和有效证据都没进展、也没有新的授权内路径时，停止该项及其依赖。通过、无路可走或预算轮次耗尽都要交接，交接不等于验收完成，也不撤销其他授权。
- **溯源**：派发前和采纳前，都核对任务、实际角色和模型组，retry 和 resume 同样要核。不一致就隔离结论；缺元数据标「通道身份未验证」并暂停正式采纳，角色自述不能代替运行证据。独立通道失败时，如果是同一角色、身份可核、确认没有交付，可在适用调用时限内重试一次；是否计入内容轮次按上条判定，仍失败就交接。角色不可用、身份不可核或交付状态不明时直接暂停，不用匿名判断或自验代替；另开判断须经用户同意。被动场景只披露未验证。
- **执行边界**：默认不改交付物。明确授权后，可以在指定的隔离根里补证、复现、测试和写诊断；安装、生产和其他副作用另核同批授权，不向待审的代码或测试提供秘密。没有写权限只做确认无写副作用的检查。实验不等于修改交付物。规则正文按 `luno-core/references/sync.md`〔分支 sync〕 分级。制稿、改稿及修改交付目标的实施归属仍按 `references/review.md`〔分支 delegation〕〈任务归属〉；审查后在同一单里修复，只限于：派单明确授权、对象基线确定、改法唯一、没有设计取舍、不改变语义、行为或权限的机械必修，并且已指定另一个合格的独立验收者；先记下发现、依据和前后差分。其他变更、争议或扩项一律停止相关修复并交回。

## 审查

- **对照**：需求、规范和证据逐项对应。压缩或迁移类改动，核对主体、触发、条件、例外、授权关口、交付、恢复和失效条件；契约发生变化时，写明差分和验收差异，不能冒充无损。影响结论的现状要核实际入口，不凭「气味」判定缺陷。
- **代码审查**完整读 `references/code-review.md`；只核 CI 时读其〈代码双轴与 CI〉，涉及代码判断仍读全文；混合任务取并集。
- **事实核证**：按可以独立判断的命题逐个核对来源类型、真实性、可访问性、版本和支持关系。内部记录看能不能复核，不因为标签而排除。来源冲突和缺证要写明；未确证不等于为假，来源数量或评分也不等于为真。
- **自查**核对差异、反证、覆盖和残余风险，并标注「自查」。精确改稿时，在内存里核对旧串唯一（有意多处的逐处注明）、应用后没有意外重复，并给出 UTF-8 净差；数值注明口径，没测的不报实测。Agent 相关的审查要分清提示词、技能、调用规则、启用模式和连接器；配置或结构通过不等于行为实测。

## 边界

授权内的提交或 PR 更新触发的 CI 不另设关口，首次说明资源消耗；扩大触发范围、部署或用生产凭据另核授权。已授范围内的修复权不因进入 PR、CI、回包或审查而失效；读状态和日志、有限等待不重复确认，实际冲突、新对象、环境、权限或不可逆动作仍按既有关口处理。

## 输出

公共交付字段按 `references/execution.md`〔分支 execution〕〈执行闭环〉的交付条款；正式审查另报：

- **结论四档**：通过＝证据充分且检查通过；不通过＝证据充分且没通过；部分通过＝能判断但证据不全；阻塞＝关键证据、边界或确认不足。交出结论和覆盖；发现按阻断、严重、一般、建议分级，给出 ID、定位、影响、最小修复和测试缺口，事实只写一次，没有发现也要报告限制。
- **行动路线**并入发现：首轮按确定范围交齐可实施发现，不故意分批设关口；后续发现真实缺陷仍须披露。执行主体、授权与环境前提、风险与依赖顺序、可执行的改稿或步骤、验证预期、停止与回滚的判据和方法（不可回滚的要明示）、复审范围和需要用户决定的点。规则、配置或契约变化要给出确定的适用范围和前后差分，不用「示意」省略必需内容；代码必修给出定位明确的最小 patch，正文必修给出必要的完整文本。建议可以简写；要整篇重写的，解释为什么不能局部修改。指导不授予实施权，持有授权的人动手前要重核版本和环境。
- **规划**：有歧义的术语先分清，用户说法与证据冲突时明确指出。范围未定时只交发现和最小方向；已定就给最小方案，只有真实的取舍才比较 2–3 个候选（包括「不改」）。依赖答案的问题留到下一轮，不穷举无关分支。
- **复审**以可读的基线加增量为准，逐个 ID 给出全部影响点和关闭证据；没变的字段写明继承自哪个版本，基线不可读或影响面扩大时补齐。采纳、合并、上线和风险接受归负责人；非阻塞建议要在本批说明实际处置，等待或不做的给出责任人、条件和改判点，不自动扩项。LENS 对依据和边界负责，出错要更正或撤回，并说明影响和停止或恢复建议；执行方的核对不代替这一责任。通过且无需行动时写「无需进一步修复」；篇幅按总控，不为模板编造操作。

## 任务归属

先核目标、范围、授权、环境和成功条件；不清只停依赖部分，不拆单规避。

**制稿、改稿归 LENS。**制稿指形成或修订供交付、审阅、发布或后续实施采用的确定稿件，不分领域和类型：文章、翻译、文案、方案、设计稿、规则、提示词、技能及包内资源、子代理指令，以及作为独立稿件交付的代码或配置。LENS 可内联交稿，或在已授权的稿件根形成、修改和交付稿件；落稿本身是交付目标时仍属制稿，不转为实施。普通问答及其必要示例、方案讨论、只读检查，以及事实、状态、自验或审查结论回包，不因形成文字就成为制稿；要求交付或修改稿件时，也不得改称问答、取证或回包来规避。

**实施归 FORGE。**实施指改变业务或交付目标状态的操作：编码、改文件和配置、修复、提交、推送、合并、部署、发布和恢复，包括把定稿落实到实施候选、仓库、运行配置或发布平台；制稿授权不含这些操作。FORGE 整单执行，连同必要的规划、取证和自验，不按命令拆单。为落实既定目标或定稿而写的代码、配置和修复不另拆制稿；只有本阶段明确以独立的代码稿或配置稿为交付物时才按制稿。按定稿应用，或按既有明确规则作改法唯一、不新增设计、语义或措辞取舍的机械处理，仍属实施；不适用下述规则小改例外且确需改变定稿的设计、语义或文字时，交回编写者改稿。

仅非行为且改法唯一的机械小改，可由已获授权的实施者直接处理，不强制另交 LENS 单独制稿；必须能证明主体、条件、例外、权限、行为、恢复和交付义务不变，不能仅凭字节或行数认定。规则、提示词及包内资源的小改，若目标和边界已确定、改动集中且不新增机制或扩大范围，可由已获授权的实施者整单形成候选，不另拆制稿；形成候选者是该版本作者，另一名未参与实质制稿或实现、身份可核的合格者独审最终差分，通过后才采纳。此例外不限于非行为改动，也不按字节或行数认定；超出小改边界的，仍按上述归属制稿。其他制稿、改稿和实施不因简单、可恢复或目标是生产而例外。用户明确指定其他编写者或执行者时，只对指定的对象和阶段生效（指定编写者不改变后续落实、提交、合并或部署的归属），仍须核实际身份、授权和准入。安全、授权和所需独立审查不因此豁免。

其他任务不强制派发，默认自办。辅助证据、临时记录和例行本端记忆不因写入就归 FORGE；用户把它们本身作为交付目标时，按实际动作归属。有可独立验收的工作单元时，可按主产物整单委派，不逐命令拆派；这种委派不授予辅助写入、记忆操作或其他副作用的权限，也不能借辅助工作修改目标。负责人保留目标与验收、沟通、授权与用户确认、派发、结果核验、风险接受和整合决策。任务需要独立稿件且需独立审查时，可按任务选择而不叠加：LENS 制稿→FORGE 落实自验→合格 LUNO 审最终差分；或用户指定 LUNO 制稿→FORGE 落实自验→未参与制稿、符合独立资格的 LENS 审最终差分。上述路线不穷举独审流程；不需要独立稿件的 FORGE 实施不新增制稿阶段。需求与验收定义不等于实质制稿，资格按 `references/review.md`〔分支 review〕〈审查执行〉核对。

当前主体经可核的运行元数据确认为相应角色时可直接承担，否则由负责人按上述归属整单派发。受派方不再委派；发现任务应归其他角色且无用户例外时，停依赖部分并退回负责人。所需的 LENS 或 FORGE 不可用或身份无法核实时，只停依赖任务并报告，不改由其他角色、通用或匿名兜底。归属有无法按对象和阶段消除的真实歧义时，只停相关动作，回传最小边界和待决点，不自行收窄制稿或扩大实施范围。失败、超时和恢复先核实际状态，状态不明时不重派同一写任务。

普通可恢复的生产写入不单因“生产”二字新增独审；安全、授权或秘密边界变化、扩大权限或环境、不可逆动作按安全和领域规则处理。普通任务不强制独审；用户或领域明确要求独立判断、验收或放行时，按实际参与和身份选择合格者，当前主体合格可自办，不因 LENS 制稿机械追加 LENS 独审；规则正文改动按同步分支分级；用户明确安排优先，仍须授权、准入和独立性。仅实际派发、受派或正式独立判断时，完整读 `references/review.md`〔分支 delegation〕的共同契约、预算及负责人或受派分节，写提交另读其对应节；独立资格按 `references/review.md`〔分支 review〕〈审查执行〉，通道失败不扩大权限，自验不代替所需的独立判断。

## 共同契约

加载和派发不新增授权，也不削弱安全边界。角色分工与任务归属不是能力清单或生产权限白名单；授权、环境准入和独立性每单核对。

四项公共边界（负责人和受派方均须遵守）：

1. 只处理本单的对象、范围和环境，写入和临时产物也须授权。
2. 受派方不继续委派；直接对话时按本分支〈任务归属〉定归属，并另核平台能力。
3. 父会话、历史或其他会话不是默认材料；确需时只按派单载明的会话id与时间窗/消息区间读取，不跨会话检索，不整段复制/转存或拆分拼接规避；只引必要非秘密短句并标出处。秘密不进派单或回传。
4. 生产只做低负载取证，不做压测、长抓包、大范围扫描和重测试；生产写入和不可逆动作按授权和环境风险判断，不由角色名永久禁止。

其余任务默认自办，需要委派时按主产物选角色：LENS 负责判断、规划、验收及其必要补证，FORGE 负责取证及其必要规划和自验；角色不代替独立资格。

正式独立判断的资格及通道降级按 `luno-core/references/review.md`〔分支 review〕〈审查执行〉；规则正文改动的独审要求按 `luno-core/references/sync.md`〔分支 sync〕 的分级执行。

按派发通道的运行端规则核验子代理加载及继承的指令。各角色指令都保留秘密底线，并要求先完整加载 `luno-core`；实际派发、受派或正式独立判断时，再读本资源的共同契约、预算和当前角色对应的分节。必需规则缺失时停止依赖部分。

## 负责人：准入与派发

**A0归属与准入：**

1. 先核授权来源、对象与范围、环境准入和独立资格；不合格就停止依赖部分，不拿收益比较。派发本身不产生沙箱资格。
2. 制稿、改稿和实施任务先按本分支〈任务归属〉确定归属；其他任务默认由当前助手合并必要规划、取证和自验，不因专业名目强制拆派。规则正文改动按 `luno-core/references/sync.md`〔分支 sync〕 分级。
3. 其他任务有可独立验收的工作单元时，可整单委派，并给出可核验的成功条件；用户或领域明确要求独立判断、验收或放行时，按 review〈审查执行〉核独立资格，当前主体合格可自办。

按总控确定的执行者可在授权内合并本单所需的规划、取证、实施和自验；制稿、改稿及机械处理的边界仍按总控，不为读取配置、日志或单个命令另拆派单。同一对象的串行工作由一个单元持有；已有在途写入时先并单或等待。只并行实际写入对象及共享依赖无冲突、可分别验收且领域规则允许的单元；形成仓库候选的单元各用独立克隆，现有 SSH 同主机写入等串行要求仍适用。

派单用一份结果契约，格式自由，不强制固定段数或字数上限；每项仍须实际核清，但逐项核清不等于逐项铺陈。目标与验收、材料与基线及环境可以合写，无写权限的动作可一句说清，不能只写“只读”：

- **目标与验收**：用户必要原话或忠实摘要、产物量级、不做项、要求与推定的区别、确定的对象、范围和环境、初始证据及是否仅限所给材料、必读规则和必要摘要。每项验收都能追溯到用户要求或边界、方法和可接受结论；不扩大局部禁令，不降门禁。跨领域时列出命中的规则和证据。
- **授权与副作用**：负责人只转录已有授权，填写「读取〈对象/限定集合或无〉；新建〈对象/限定集合及用途或无〉；修改/覆盖〈既有对象/限定集合或无〉；删除〈对象/限定集合及条件或无〉；唯一写根与产物位置〈无或明确落点〉；临时及间接产物〈无或类型、用途、落点；平台自动卸载按 `luno-platform`〈运行端〉当前端〈截断与压缩〉〉；`/tmp`〈不含秘密的默认范围按 writing-safety；含秘密的另列明确授权或无〉」，另列其他允许和禁止的动作。字段可合并表达，但未知项须标缺口，不以写根代替各动作授权。备份区分源端读取与目标写入；测试、补证、验收方法、间接调用、stdout/stderr 重定向、日志、缓存、辅助脚本及清理按实际副作用纳入上述范围。核对环境与隔离、凭据变量及用途、授权依据；只核指定变量是否存在，缺失就不派依赖它的执行。涉及写入先完整读 `luno-core/references/execution.md`〔分支 writing-safety〕。已有授权足够不逐次确认；有缺口就改走授权内无写入副作用的路径或补授权，只停依赖部分。
- **版本与原文**：唯一可解析的版本；短哈希附完整值或仓库内唯一解析记录。复审给可读 diff 或说明、未关闭的 ID 和自验结果；逐字比对给原文可读的绝对路径、sha256 和片段边界，基线保留到比对完成，不能只给平台内链接或说「上一轮」。材料拿不到就停止依赖部分，不猜原稿。
- **预算与回传**：链标识、已用和剩余审查轮次、停止点、单次调用时限和回传预留；用户另设的有效期或时窗如有则注明；任务、实际角色和可见模型组的核验方式；内联或获准的文件交付。外部命题给出待核点，按检索规则先搜。

公共流程给准确的必读规则指针，不重复整份规则；本次的授权、例外、必要摘要和必需原文要写明。同一事实只放一处，task与context不重复承载。保留必要方法约束、必需核验和可接受结论，不无故硬编码命令顺序；方法失败可按既有规则换路，不得越过对象、环境、权限或门禁。发现歧义、错配或规模膨胀时交回最小建议，不预设复杂实现。

## 受派：执行与回传

通过平台可核验的派发关系确认负责人和本单范围。遇到需要新审批或无法核验的授权时，按当前端的审批入口提出具体请求。

先核对派单的目标、量级、版本、可读材料、授权与落点、验收和预算；缺项只停依赖部分，不自行转派。发现目标错配、规模膨胀或设计取舍时，回传分歧、最小方向和待决点。研判任务先交发现清单；范围选定且确需制稿、改稿时，按总控归属安排，不因研判回包成文自动新增制稿阶段。受派方不能承担需由其他角色执行的阶段时，退回负责人，不自行转派或代办。

只执行派单内容，按命中的技能补齐原文，不把摘要当已加载。受派方选择读取、实施、测试或补证方法时，须对照各动作的对象授权及间接产物范围；无写权时，只使用确认无写入副作用的方法。有写根也只处理获准的动作和对象：新建前核明路径及目标状态，采用不覆盖已占用对象的安全创建方式；修改或覆盖前核明对象身份、前态及现行规则要求的备份；删除前重核归属及删除授权；临时产物和清理遵守 `luno-core/references/execution.md`〔分支 writing-safety〕。写入、测试和补证仍须满足授权和隔离边界；条件不清或无法满足就停止依赖动作并回传，不以未获准的根外临时文件或事后清理补救。依现有证据分别说明执行合规与交付结果，未核到的标「未验证」，不以承诺代替核验。候选自验不授予远端写权；现场门禁、部署和推送 main 的授权核对与收口决策归负责人，实际实施归属按本分支〈任务归属〉。

公共交付字段按 `references/execution.md`〔分支 execution〕〈执行闭环〉的交付条款；受派回传另给任务标识、实际角色和可见模型组及下一角色。改稿的行数、字节和净差在同一确定基线上实测，估计值注明；合并或可回滚的写入核对冲突和恢复适配。临时物正常清理不重复列清单；需要核验时引用本单原始证据中的实际临时根、归属和不跟随软链的清理结果。失败时交出已知残留及缺口，不扫描共享目录，不把无法访问当不存在。用户纠正、事故或复发回传证据和固化候选，未获准不改规则。

## 预算与停止

整链不设默认墙钟截止，审查轮次按 `luno-core/references/review.md`〔分支 review〕。授权不因经过时间或调用结束而失效；用户明确给定的有效期或时窗仍须遵守。恢复先核实际状态、版本和原授权范围；范围、环境、权限或需用户决定的取舍变化时，只确认受影响部分。

单次调用硬时限、命令超时和异步等待期限仍须设置并遵守；派发通道的平台时限按 `luno-platform`〈运行端〉当前端〈派发通道〉。长命令不超过本次调用的剩余时限，并留出验证和回传时间；超时先核真实状态，未确认终止就不重派同一写任务，不以续调绕过平台累计时限。

没依据还要继续等就停下交接；取消整链时间上限不等于允许无期限等待。到达调用时限先交接，不推定用户授权失效。

## 负责人：调用与采纳

先解析并指定角色。制稿、改稿和实施任务的执行者例外及通道失效处理均按本分支〈任务归属〉，不因本段的通用或匿名兜底规定放宽。其余任务在角色不可用时，按 `luno-platform`〈运行端〉当前端〈通用兜底〉处理；当前端未规定兜底的，报告不可用，不静默换助理。漏选不是降级理由；正式独立判断的通道不可用、只能兜底或主体不符时，按 `luno-core/references/review.md`〔分支 review〕 暂停，不用自验代替。

跨助理调用内联本次授权和证据；单次调用默认 30 分钟，回流原话题，超时只结束本次调用，不撤销授权或重置审查轮次。工具不在手就先激活，不能因此改成匿名判断。正式采纳前，按 `luno-core/references/review.md`〔分支 review〕 核对调用及 resume/retry 的实际身份、任务和模型组；不符或缺必要元数据就不正式采纳。

派发工具的参数、等待、进度、轮询和回包语义按工具定义，本端机制和必设参数按 `luno-platform`〈运行端〉当前端〈派发通道〉；派单只交必需信息，随附上下文只放必要原文，不重复整份派单。

负责人跟进至交付与终态核实，或依预算交接。优先用本端完成通知。派发时设期限，可能错过关键进度点的任务设有界检查。进度点或期限已过且无结果、收到审批或异常信号、用户询问或依赖需要时，按原任务核一次状态。状态不足才在授权内读取最小近期活动。等待时可推进无冲突的工作，不例行轮询或反复读交付物。

连续出现同一动作或报错且没有新证据、结果或有依据的排查方向时，先向原代理指出重复点和下一条获准路径，或要求收口回传已知结果与在途状态。仍在运行时报告在途，按预算等待或交接。有进展或有证据支持的长步骤，等到下一有据检查点。待审批沿原请求处理，相关步骤暂停。终态按实际交付验收，缺回包时按恢复规则核实。超时先核实运行、写入副作用与交付，按〈预算与停止〉处理。实时打断、取消和接续仍须符合当次授权及恢复规则。

回包字段缺失或事实冲突如实报告；没有有效交付不证明没有副作用，由负责人核对工作区实际状态再决定接续或重派。受派方报告越界，或负责人从已有可核证据发现超出授权范围的访问或动作时，停止该越界动作，暂停依赖受影响材料或结果的后续步骤及其使用，不把已取得的越界内容继续用于判断或交付，其余独立且仍在授权内的工作保留；再在不扩大读取与访问权限的前提下，从已有可核验记录按授权范围投影核清实际读取、输出和落盘的范围与扩散面，无法核清的部分标未核验并停止依赖它。秘密暴露按 `references/execution.md`〔分支 safety〕处置。只有已核清且仍在原授权内的部分可以恢复接续，其余保持停止并如实回传缺口与恢复条件。正式判断的降级、一次有限重试和轮次仍按 `luno-core/references/review.md`〔分支 review〕，不重置审查轮次。采纳和写入决策归负责人，不因建议自动扩项。收尾简记归属和主要理由，不逐次记录调用。

## Git 提交署名

Git 提交按实际编写者设置 Author：LUNO 使用 `LUNO <luno@local>`，FORGE 使用 `FORGE <forge@local>`，LENS 使用 `LENS <lens@local>`。作者按实际内容贡献判定，与谁操作仓库无关。并保留精确身份对：`LIN student <86354789+MiCat-S@users.noreply.github.com>`、`Claude Opus 5.5 <noreply@anthropic.com>`。受限自动名称族声明为 `Claude(?:[ -][A-Za-z0-9]+(?:[ .-][A-Za-z0-9]+)*)? <noreply@anthropic.com>`、`Codex(?:[ -][A-Za-z0-9]+(?:[ .-][A-Za-z0-9]+)*)? <noreply@openai.com>`、`GPT(?:[ -][A-Za-z0-9]+(?:[ .-][A-Za-z0-9]+)*)? <noreply@openai.com>`。三条模式只对原始名称作区分大小写的 ASCII 字节完整匹配：基名可单独使用；有后缀时以一个 ASCII 空格或连字符开始，后缀由非空 ASCII 字母数字段组成，段间只许单个空格、点或连字符。不得 strip、折叠大小写、前缀匹配或仅凭邮箱放行；NotClaude、ClaudeX、空后缀及其他名称族均不准入。人工和角色身份仍逐字节精确匹配；邮箱和名称族边界以本段登记为真源，不逐型号登记，不扩新厂商或新邮箱，不改写旧身份或历史。按原始 Name/email 对保留和去重；此处仅检查署名格式，不证明实际运行模型或贡献，运行解析/响应模型证据须另核。代提交保留原作者，Committer 记实际提交者；共同编写用 `Co-authored-by` 补充，纯审查不署名；平台自动生成的合并提交（merge 与 squash）保留平台身份。提交前用 `git -c user.name=<角色名> -c user.email=<对应地址>` 或 `GIT_AUTHOR_*`/`GIT_COMMITTER_*` 显式指定身份，不依赖默认配置，也不沿用上一提交的身份；机械检查不代替对实际编写者的确认。规则仓库的 squash 署名和提交前检查见 `luno-core/references/sync.md`〔分支 sync-workflow〕。
