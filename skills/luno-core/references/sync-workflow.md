# 规则变更与同步流程

## 风险分级

改规则或提示词前先定级；定级不授予写权限，拿不准或有争议的按高风险处理。

- **非行为低风险**：只改错别字或排版（不改变解释）、删除精确重复、移动来源说明，或把同一义务逐字搬到别处且加载闭包、触发和适用范围不变；须能逐项证明主体、条件、例外、权限、行为、恢复和交付义务都没变。可在已授权的独立候选里直接实施，必要校验后做**一次独立差分验收**，通过且负责人核验采纳后才能合并或部署，不需要改前预审。
- **其他或高风险**：涉及安全、授权、秘密、加载或路由、角色或派发、审批或执行语义、恢复、领域严格门禁或专业能力的改动，以及无法证明没有行为变化的改写，都要先提交确定的对象和基线、逐字改稿、验证和回滚方案，经独立预审明确通过、负责人核验采纳后才修改候选；实施后的差分再做独立验收。本文件自身的修改也属于这一类，不能用尚未生效的规则给当前批次豁免。

分级理由、实际 diff 和逐项义务对照写进本批 PR，验收时核对分级是否成立；需要升级或无法判定就停止合并和部署，按高风险补预审，获准后重新实施和验收，不用既成候选倒推通过。拟稿者不预审自己的改稿，实施者不验收自己的版本；身份溯源、结论和降级按 `luno-core/references/review.md`。只同步已经完成审查或验收、内容没变的版本时，不重开轮次；版本、证据、范围或结论出现疑点时按 review 复审，预算不重置。

## 同步顺序

**独立副本或分支上修改 → 必要校验 → GitHub 原生 PR → 串行合并 → 备份将被覆盖的对象 → 按合并的变化同步 → 逐端回读。**不使用自研的发布状态机、冻结链、摘要账本、档案窄提交或机器证据回执；不要求每次正文同步都跑全仓重测试或全端巡检。

1. **副本**：每个会话用独立 clone 和唯一任务分支；Minis 上的候选放在 `/var/minis/shared/agent-sync-candidates/<会话标识>/`，不放 `workspace/`，也不用共享 `.git` 的 worktree。一份副本只有一个写入者；各会话只推自己的分支和 PR，不推 main，不写共享集成副本。由负责人指定的收口者逐个合并，并串行部署同一生效对象。原生 PR 承载差分和合并冲突，但不声称能自动解决语义冲突或平台竞态。
2. **校验**：先读本批 diff 和 `PENDING.md`，核对授权、变化对象和登记落点。只跑变更路径命中的必要测试（以 `tests/run-tests.sh` 的选路为准），纯正文改动跑 `smoke`。`tools/sync-all.sh` 只跑结构守卫和包内校验，不读生效端；rc=1 或 3 阻断，rc=2 只是提示。登记或公共工具变化时，完整执行它们的实际消费者。结构守卫只查加载边、资源边、登记身份、包内引用和义务块是否存在，不比对正文；防止正文弱化靠本文件的分级和独立审查。改动加载边或资源边要在同批更新 `tools/rule-claims.tsv`。
3. **提交、PR 与合并**：审阅暂存 diff，显式 `git add <本批路径>` 后普通提交，推到本会话任务分支（不强推），用 `gh pr create` 开原生 PR。合并前读最新 main；基线前进就普通 merge main 到本分支，逐处处理冲突并重跑受影响的测试，不用 union、整份选边或强推。收口者确认上一个 PR 已合并后再合下一个。
4. **备份**：只同步已授权的变化对象及其包内资源，按 `tools/sync-targets.json` 找目标；未登记的先登记，不顺带改无关的端。覆盖前备份目标的**实际生效前态**（正文、资源和将改的元数据）到本批资产目录，核对可读、内容和权限；不拿候选副本冒充前态。不要求全仓恢复包或预演未改对象的恢复。
5. **写入**：按平台支持的入口写入，默认同步授权和例外见本技能〈真源与落点〉。写入前核对目标实际生效值仍与已核基线一致；发现并发变更就停止相关对象并重核差分，需取舍时回到确认。LobeHub 同一 identifier 优先原位更新保留 ID；只有无法原位更新且明确授权迁移时，才备份后重建并联动来源登记。Minis 只改正文不需刷新登记，frontmatter 或元数据变化按平台技能流程处理。秘密不进入诊断、备份清单、提交或派发材料。
6. **回读**：对**本次变化的对象**在各登记落端回读：正文和资源逐字节一致，name、description 等变化字段另核；提示词同时核对生效字段和文件视图。不用安装成功、HTTP 200、CI 变绿或文件存在冒充一致。端间允许过渡态；失败只停相关对象，列明已同步和未同步的部分，保留真实前态和恢复办法，不报整批完成，不盲目重投。恢复写入也须在授权内。

不提供全端聚合巡检或「未变豁免」参数。MCP 按本批授权直接核对涉及的配置；URL 参数值不输出，只投影参数名和工具选择状态。普通正文同步不自动扩项。没访问或没核验的端和 MCP 明确写「未核验」，不声称已通过。

## 本仓库的合并与署名

- **只用 squash 合并**：用户已就本仓库明确授权，批准合并即包含删除该 PR 的源分支，所以用 `gh pr merge --squash --delete-branch` 收口，不需另行确认；删除只限该 PR 自己的源分支，用户声明保留的照办，失败如实记录，不扩大清理范围。合并后用 `gh api` 回读 merged 状态、main 上的提交（应为单父、Committer 是 GitHub web-flow 且已签名）和源分支已删除。远端再次前进就重新核对差分，不盲目重投。
- **squash 提交说明**（合并时填写的标题和正文，会随合并落库）：为 PR 内**每个提交的 Author**，以及去重后的 `Co-authored-by`，各写一行 `Co-authored-by: 名 <邮箱>`。身份取自 PR 提交的原始字节（`git cat-file commit`），不按平台显示的账号名改写。
- **身份判定**：署名身份见 `luno-core/references/delegation.md`〈Git 提交署名〉。普通提交的编写身份按 Author 和合法的 `Co-authored-by` 的并集去重判定：同一身份写了多行、或多个提交属于同一人，只算一次，不判违规；但普通提交的尾行与 Author 相同仍判违规。只有 squash 提交允许尾行与 Author 相同（它的 Author 是 PR 内最后一个提交的作者，按原字节逐行写时必然重合）。平台自动生成的合并和 squash 提交不要求、也不另加作者行。
- **机械检查**：提交后、推送前，必须运行 `python3 -B tools/check-commit-identities.py --base <已核的基线提交> --head HEAD` 并通过，CI 再按 PR 的 base..head 复核。push 到 main 时，检查器放行「单父、Committer 是 GitHub web-flow 且签名经 `tools/github-web-flow.gpg` 验证通过」的提交，同时要求它的 `Co-authored-by` 非空且逐条合规；空范围、缺行或不实署名都判违规，不因为是 squash 就豁免。
- 只从确认已合并的版本取变化对象部署；仓库合并不等于线上同步成功，没部署或部分成功都要如实记录。共享集成副本只由收口者在干净状态下快进更新，其他会话不写。开 PR、合并和实际部署分别核对既有授权，校验脚本不会自动执行这些写入。

## 记录与恢复

本批 PR 一次性记录对象和改动、实际校验、提交和远端回读、各端部署和回读，以及未完成的状态；正式的独立审查附上对象版本和脱敏后的结论。合并后据实补充 PR，不为补记另开 PR 或提交，也不预先填写成功。不再新增逐日 changelog，也不在 PENDING 里归档全文副本；既有的历史记录保留，不清理恢复证据。

活动中的未决事项只放在 `PENDING.md`：写对象、条件或承接的批次、责任人和必要的恢复指针。新一批只复检相关的项；本批已授权的工作直接做完，不列等待。决定不做的记在本批 PR 里（理由、改判条件、责任人），条件没变就不重开；只能等真实场景的被动观察只披露未验证，不挂待办。

记录里不写秘密、主机名或本机路径。合并前发现的错误在原分支修正后复核；中断或失败时，先核对工作区、远端和已改目标的实际状态，再按授权接续或恢复，保留实际前态和恢复限制。

## 变更纪律

改动前定位源头、引用方、登记和必要的副本。声明改稿或副本与某个源片段「同文」「逐字一致」时，预审和改后回读都要按明确的片段边界和既定的正文提取口径，用程序比对 UTF-8 字节，不自行去前缀、strip 或归一换行。改完回读所有目标，报告旧→新、UTF-8 净差，以及实际运行的测试集合和耗时，不拿计数当覆盖。规则真源和字段判等按本技能入口；候选不等于生效值，尚未部署的规则不改变当前的执行边界。改动以最小为先，优先净减；保留有意的冗余，不借精简削弱秘密、授权、隔离和写后回读的要求。

**来源与许可**：第三方吸收件的运行正文须留必要作者/许可、改写性质及来源登记指针；完整上游仓库@提交、路径、日期、取材边界和可取性记在 skills-sources.md 或该对象包内来源登记，许可全文仍随包分发。仅下沉详细来源不删除证据或扩大分发权；新增吸收/退役另核对象授权，缺来源不称完成。

**主动补规则**只有一种例外：问题在本会话里已经发生、造成了后果、因果已经核实，并且该文件已有维护授权。缺任何一项都只能把建议交给发起方，禁止自行写入。巡检诊断按总控的源头投影只取非秘密字段；完整恢复备份不能用来取密或交互输出。
