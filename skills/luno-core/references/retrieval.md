# 联网检索

## 外发边界

向第三方搜索或抓取服务提交查询、URL 或正文之前，先核对既有的外发范围和授权；查询、URL 和正文里不能夹带秘密值。非公开的个人信息、非公开的内部信息、非公开 URL 和需要登录才能看到的内容，只有既有授权明确覆盖向相应服务外发这类数据时才处理；没有授权只停这一项外发，不扩大成全面禁止检索。公开材料（包括任务需要的公开个人信息）在既有检索授权内直接处理，不逐次确认。检索授权不代替密钥引用授权。

## 怎么搜

- **先搜再答**：不以「本地没有记录」为前提，官方文档和上游 issue 优先；不为省额度跳过必要的检索。参数明确就直接调用，不重复确认；以够判断为准，不设条数或次数上限。
- **选工具**：默认用 Exa；精确文本、长尾内容、站点或日期筛选用 Keenable；结果不够再换源，已知 URL 直接读。关键结论鼓励用两者交叉核对。读取非时效性的正文先用 Exa，可以批量；遇到空文、错误或拦截页、目录占位或缺少所需段落时，换 Keenable 再取一次，不单凭长度重抓；需要最新原文时用工具已支持的实时抓取。
- **工具可用性**：优先使用本端可用的 Exa/Keenable MCP。调用前先读工具定义并核对授权；工具名、参数、认证和请求方式以实际的工具定义为准，不预设本端能力。所需 MCP 不可用时如实报告；仍可在既有授权内使用本端可用的原生或浏览器搜索，或直接读取已知的公开 URL，但不自动改走 REST，不套用另一端的 CLI，也不猜参数。入口可见或配置存在不证明连通或调用成功。

## 怎么用结果

- **结果只是候选，不是验证**。深入研究时把问题分成已答、冲突、未答三类，按缺口推进，继续搜索对判断没有帮助时就停。
- **来源要求**：每个关键结论至少有一个可核验的原文来源（URL、日期、版本）；外部事实要附来源。取不到的标「未核实」，不作为定论的前提，不靠推测补证或凑证据。篇幅受限时优先保留关键证据。
- **时间语义**：区分发布日期、索引时间、缓存年龄和历史快照；历史内容不等于历史排序，限定历史索引也不等于拿到了历史原文。时间筛选和新鲜度的语义按实际工具支持核对。即使调用成功，也要逐个 URL 核验正文；定向提取或摘要不能代替对原文的验证。
- **HTTP 状态码**（仅当工具实际暴露时按码处理）：401 停止并报告认证问题，禁止转为匿名访问；403 按错误体分清本方权限或策略问题与源站拒绝，不误报为认证故障，也不盲目重试；429 按 Retry-After 或指数退避有限重试，用尽就报告。没有暴露状态码时不猜；前置代理或访问层的错误不能当成服务端错误。

## 公开代理回退

已有的正文抓取方式都失败后，只对 URL 和内容都明确允许向第三方公开披露的 HTTP(S) 页面，可以改用 `https://defuddle.md/<目标URL>`，失败再试 `https://r.jina.ai/<目标URL>`。这两个都是第三方服务，目标 URL 会暴露给它们。

- URL 的路径、查询或片段里含有凭据、userinfo、令牌或签名参数、个人或内部信息的，私网或本地地址，以及依赖登录态的页面，都不得转发；不附带浏览器 Cookie 或认证头。转发授权或目标是否公开不明确时，不用这个回退，也不借代理绕过访问控制。
- 返回结果要核对目标、关键段落和日期；不把代理生成的摘要、拦截页或缓存当作完整的最新原文。
