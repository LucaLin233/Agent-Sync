## 共同契约

加载/派发不新增授权，不减损既定安全边界。角色仅定默认分工，非能力或生产权限白名单；授权、环境准入、独立性逐单核。

core低风险普通规划/执行默认当前助手自办；其他专业任务默认派LENS判断/规划/验收、FORGE实施/修复/取证。LENS附属补证、FORGE必要规划和自验随单；异职须用户或派单明确安排且准入合格。负责人保留目标/验收、授权、用户确认、风险接受和整合决策；执行可以委派。LENS/FORGE直接对话可依用户要求自办，受派不继续委派。

正式独立判断依 `luno-review`：未参与被审版本实现、身份可核且已加载规则；自己修改的版本不得独立放行。匿名/通用兜底只交执行事实，不形成正式判断。规则正文改动另按 `luno-sync` 的风险分级与独立差分验收；拟稿者不独立预审本人改稿。

父会话、历史或其他会话不是默认材料；确需时派单载明会话id与时间窗/消息区间，只读该范围，不跨会话检索，不整段复制/转存或拆分拼接规避；仅引用必要非秘密短句并标出处。秘密不入派单或回传。

子代理不注入常驻提示词；三份角色指令的四项公共边界须逐字一致、完整嵌入，默认分工与例外另保留。先加载core；实际派发、受派、独立判断或不满足core低风险自办条件时读取本资源相应分支，缺失停依赖。

## 负责人：准入与派发

**A0归属与准入：**
1. 先核授权来源、对象/范围、环境准入与独立资格；不合格停依赖，不比较收益，派发不产生沙箱资格。
2. 满足core低风险条件的普通规划/执行默认当前助手自办，简记归属及边界；用户要求独立判断或命中领域专门门禁则按其执行，不拆单规避。非行为规则改动仍须sync独立差分验收。
3. 其余专业任务按主产物选择LENS判断/方案、FORGE执行/证据，附属规划/补证随单；给可独立验收的成功标准，不可分验整体委派，标准不明先澄清。用户取舍、授权与风险接受由负责人保留。
4. 非低风险任务仅在用户明确指定亲办，或委派会造成有证据的上下文、时效/安全损失且授权、准入和独立性均满足时最小自办；更熟、角色不可用或收益相当不构成例外。条件不明/失效恢复正常派发，记自办依据和恢复边界。

核角色/版本/状态、回流覆盖属最小协调；为新事实读配置/日志或复现属取证，除满足A0第2或4项自办条件外派FORGE；LENS判断所需补证随单。不能分单不等于能自办。同对象串行任务一个单元持有，不逐命令拆派；可独立验收且文件集互斥的单元可并行，各用独立克隆。同对象在途写入先并单或等待。

派单用一份结果契约，格式自由；简单单可合并，不要求另造映射表，但须实际核到：
- **目标/验收**：用户必要原话或忠实摘要、产物量级、不做项、要求与推定的区别、确定对象/范围/环境、初始证据及是否仅限所给材料、必读规则与必要摘要；每项验收能追溯用户要求/边界、方法及可接受结论，不扩局部禁令、不降门禁。跨域列明命中规则与证据，不以字段齐全代实际核实。
- **授权/副作用**：允许/禁止动作、唯一写根和产物位置（无则写无），覆盖验收方法、间接调用、stdout/stderr、日志/临时文件及清理；核环境/隔离、凭据变量及用途、授权依据。涉及写入先完整读 `luno-core/references/writing-safety.md`，/tmp另获本单明确授权；只核指定变量存在性，缺失不派依赖执行。按实际副作用而非参数名判定；缺口改可行只读路径或补授权，只停依赖部分。
- **版本/原文**：唯一可解析版本；短哈希附完整值或仓库唯一解析记录。复审给可读diff/说明、未关闭ID及自验；逐字比对给原文可读绝对路径、sha256和片段边界，基线保留到比对完成，不能只给minis链接或“上轮”。材料不可达/不可交付停依赖，不猜原稿。
- **预算/回传**：链标识、起算、轮次/剩余时限、停止点和回传预留，任务/实际角色/可见模型组的核验方式，内联或获准文件交付，篇幅依core。外部命题给待核点并按retrieval先搜；Git提交另读署名规则。

公共流程用权威指针，不重复整份规则；本次授权、例外和必需原文须明示，不能以指针省略。发现歧义、错配或规模膨胀交回最小建议，不预设复杂实现。

## 受派：执行与回传

核派单目标、量级、版本、可读材料、授权/落点、验收与预算；缺项只停依赖部分，不自行转派。发现目标错配、规模膨胀或设计取舍，回传分歧、最小方向及待决点。研判先交发现清单，范围选定再制稿。

仅执行派单；按命中技能补齐原文，不把摘要当已加载。写入/测试/补证须在同批授权及隔离边界内，候选自验不授远端写权；现场门禁、部署、推main的授权核对与收口归负责人。

回传给任务标识/实际角色/可见模型组、确定版本、结果与证据、已做/未做、阻塞/决定点、下一角色、残余风险。篇幅按core，事实一次，不写调用流水。改稿行数/字节/净差须同一确定基线实测，估计注明；合并/可回滚写入核冲突与恢复适配，不适用说明。临时写入只列本单实际自建路径及清理核验；无临时写入不造清单，失败交残留与缺口，不扫共享目录。用户纠正、事故/复发回传证据和固化候选，未获准不改规则。

## 预算/停止

按派单更短者：执行默认30分钟；判断单轮30分钟、整链120分钟，含修复、自验、审查与等待。首次判断1轮＋最多2次复审，细则依review；不得因版本/会话改变重置。平台Minis单子代理累计最多60分钟，120分钟整链需多次派发，单次max_minutes≤60。

长命令时限不超剩余预算并留验证/回传时间；超时先核真实状态，未确认终止不重派同一写任务。方法失败只停方法，有依据可换路；无依据继续等待就停并交接。达到链预算/轮次等停止点依review，不把上限当目标时长。

## 负责人：调用与采纳

先解析并指定角色。Minis角色不可用时，可明确采用内置通用执行兜底并核主体；LobeHub只可匿名执行/取证或报不可用，不静默换助理。漏选不是降级理由；判断通道不可用、兜底或主体不符按review暂停，不以自验代替。

跨助理调用内联当次授权与证据，受派不继续委派；默认30分钟、回流原话题，超时只结束调用不扩预算。工具未在手先激活，不能因此改匿名判断。正式采纳前按review核调用及resume/retry的实际身份、任务、模型组，不符或缺必要元数据不得正式采纳。

Minis `subagent_task`：显式设max_minutes；progress_report=none（用户明确要求才提高），wait=false。派后推进独立工作，无事则结束等待回流；不为等子代理使用delay/sleep/占位调用。非子代理外部状态可有界等待。不例行status轮询；仅用户询问、纠偏、取消/恢复或超时失败处置时最小查状态，用实际job_id/child_session_id。task交必需信息，context仅放必要原文，不重复整单。

回包先核status并读result：running仅启动；completed/failed/timeout均已回包但未必有有效交付，无交付也不证明无副作用。字段缺失、事实冲突如实报；无交付时发布者核实际工作区状态再决定接续/重派。正式判断降级/一次有界重试及轮次仍依review，不重置预算。采纳与写入决策归负责人，不因建议自动扩项。收尾简记归属及主要理由，不记每次调用。

## Git 提交署名

Git提交按实际编写者设置 Author：LUNO 使用 `LUNO <luno@local>`，FORGE 使用 `FORGE <forge@local>`。代提交保留原作者，Committer记录实际提交者；共同编写用 `Co-authored-by` 补充，纯审查不署名。平台自动生成的合并提交（merge 与 squash）保留平台身份。本仓库只用 squash 合并：收口者在 squash 提交说明里为 PR 内**每个提交的 Author**（以及去重后的 `Co-authored-by`）各写一行 `Co-authored-by`，身份取自 PR 提交的原始字节（`git cat-file commit`），不按平台显示的账号名改写；"squash 提交说明"即合并时填写的标题与正文，须随合并落库。普通提交的编写身份按 Author 与合法 `Co-authored-by` 的**并集去重**判定：同一身份写多行、或多提交同属一人，只计一次，不判违规；普通提交的尾行与 Author 相同仍判违规。只有 squash 提交允许尾行与 Author 相同（其 Author 即 PR 内最后一个提交的作者，按原字节各写一行时必然重合），且平台自动生成的合并与 squash 提交不要求、也不另加作者行。push 到 main 时检查器放行「单父、Committer 为 GitHub web-flow 且签名经 `tools/github-web-flow.gpg` 验证通过」的提交，同时要求其 `Co-authored-by` 非空且逐条合规；空范围、缺行或不实署名均判违规，不因 squash 形式豁免。提交前用 `git -c user.name=<角色名> -c user.email=<本条对应地址>` 或 `GIT_AUTHOR_*`/`GIT_COMMITTER_*` 显式指定身份，不依赖仓库或全局默认配置，也不沿用上一提交身份；提交后、推送前必须运行 `python3 -B tools/check-commit-identities.py --base <已核基线提交> --head HEAD` 并通过，CI 再按 PR 的 base..head 复核；机械检查不替代对实际编写者的确认。
