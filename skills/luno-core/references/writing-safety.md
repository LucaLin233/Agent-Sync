# 写入、临时产物与清理

以下规则适用于写入、重定向、日志、临时文件和清理。读取不授予写权限；stdout/stderr 重定向落盘和日志也算写入。这里只约束临时文件，不改变交付件、备份和待续证据已有的授权。

- **落点**：临时输出不用共享的固定路径。需要落盘时，只在唯一授权的工作根里新建本单独占的临时目录 `.tmp-<单元标识>/`，在受控父目录内以最小权限排他创建，并排除跟随软链和「检查后被替换」的风险；做不到就不用。已经安全创建、仍归本单独占的文件，只能在既有授权内复写。临时文件不混入交付件、备份或待续证据。
- **含秘密的临时文件**不得放在自动同步目录或跨会话产物目录，并要事先核明备份和持久性边界。在 Minis/iSH 上一律走下面的 `/tmp` 例外：用 `mktemp -d` 创建独占目录（700），文件 600，用完即删。
- **`/tmp` 例外**：只有本单另获明确的 `/tmp` 授权、并按上述要求独占创建时才可以用（一条命令也要授权）。只限在单条命令内创建、退出时清理，并核实没有残留；做不到就不用。
- **收尾清理**：每个工作单元收尾前（包括失败、暂停和交接），删除本单元自建且仍获准删除的临时文件。临时目录和本单实际自建的每个临时路径，都要逐个以不跟随软链的方式核验，确认不存在才算清理完成；无法访问不能算作不存在。清理前重新核对归属和删除授权；归属不明、权限不足或路径被替换时，不删除也不改权限，报告缺口和已知残留。
- **边界**：没有写或删授权、或工作根不明时，不新建也不删除，只交接已知残留；不扫描共享目录，不动他人或平台的文件，秘密落盘的限制不变。事后文件不存在，既不能推断事前没有原件，也不能证明没有发生覆盖、误删或泄漏。
- **汇报**：默认不提问、不汇报、不展示清单；失败或归属、授权不明时报告缺口。待删项合计 ≥500 MiB 或 ≥1000 项时，删除前说明规模；超出授权才需要确认。
