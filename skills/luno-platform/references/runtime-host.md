# 宿主端运行适配（Codex 与 Claude Code）

本资源是 `luno-platform` 入口〈运行端〉在宿主端的共用槽位约定，适用于原生 CLI 和既有 paseo 宿主。只在当前端为 Codex 或 Claude Code 时读取，并分别与 `references/runtime-codex.md`、`references/runtime-claude.md` 合用；同一槽位两处都写时以后者为准。义务、授权和停止条件以引用处为准，本资源不新增或放宽权限。

## 环境取值

运行身份、托管方式、目录、已安装依赖和实际入口以当次获准的运行元数据、明确配置及必要的有界核验为准，不因旧部署说明就假定容器、非 root、特定镜像或固定家目录。用户指定的落点优先；`~` 只表示运行进程的实际 HOME，安装器的 `--home` 只是受管安装根，不改变进程 HOME。未取得取值就停止依赖操作，不猜路径，不枚举环境、不读凭据、不广扫或跨设备探测。环境可用不授予操作权。

## 临时目录

含秘密的临时文件用 `mktemp -d` 在 `/tmp` 下创建独占目录（700），文件 600，用完即删，并满足 `luno-core/references/execution.md`〔分支 writing-safety〕中「`/tmp` 默认范围」一条的创建、清理和核验条件；不放进受管检出、任务副本或其他会被提交、同步的目录。

## 执行环境

- 在本次指定且获准的环境中核实执行入口、资源控制、权限边界和依赖。Codex 的沙箱和审批沿用该端资源及当次已核配置，适配不改这些设置。来源可信、入口及依赖已静态核对的测试可以把满足所需边界的宿主环境当作原生执行环境；root 身份、容器或最小白名单环境均不单独证明权限隔离。
- 只有实际具备并获准使用的 Docker、systemd 等能力才能使用；不因 CLI 在宿主机运行就借用主机服务、生产数据或 Docker socket。执行环境和重测试按 `luno-ops` 入口〈安全与测试〉。
- 既有宿主端安装继续按仓库 README 的宿主安装说明；本资源不要求迁移、重建或改变其用户、目录与配置。

## 秘密注入

秘密只由本次明确授权的机制按指定变量注入，不把配置或登录态当作秘密来源。宿主端的 provider `env` 和明文 `config.json` 只放非秘密值；env 文件由用户自行维护，AI 不创建、不读取。变量缺失时只报告变量名，不换来源、环境或交互补取。登录态与凭据不由规则安装器读取、复制或迁移。

## 技能根

实际技能根按对应运行端及版本的官方发现规则和本次配置核实。Paseo 中使用 Codex 运行时的角色从实际 provider 配置的 Codex 家目录发现技能。使用其他运行时的角色按该运行时单独核实技能入口。旧部署确实以专用家目录启动时，沿用该目录的技能入口；Codex 的 HOME、CODEX_HOME 和技能搜索根不能混为一项，见 `references/runtime-codex.md`。安装器支持的入口指向受管检出 `skills/<技能名>/`，安装根重定位本身不证明 CLI 会发现技能。

## 工作副本

受管检出和任务副本的位置以本次明确配置为准；受管检出只由收口者在干净状态下快进到已合并版本，供软链和安装器使用，不在其中编辑。候选使用独立 clone，一个任务一个分支、一个写入者；已获准的 paseo worktree 保留原用途，不因原生迁移自动复制或迁移。

## 远端工作目录

登录其他主机前必须取得当次获准的主机、项目目录及写入范围；未指定就停止依赖的落盘，不沿用其他端的目录或自行新建公共入口。过程产物的权限、前态、恢复和清理仍按总控及命中的 `luno-ops` 资源；项目目录 700、文件 600，保留结论性产物。

## 连接清单

只使用本次明确指定的非秘密连接配置；若来自 GLOBAL 私人副本，按下述记忆入口完整读取。未指定时报告缺口，不枚举凭据或试连默认主机。

## 记忆入口

- GLOBAL 是 Minis 唯一真源的整份单向私人只读副本，AI 不修改。确切路径以明确配置为准；内嵌模式安装器沿用 `<安装根>/.luno/memory/GLOBAL.md`。Codex 单端显式选择 `--codex-global-source paseo-append-system-prompt` 时，私人目标改为已核 daemon 的 `daemon.appendSystemPrompt`，不再另设宿主文件副本；角色 home 的 `AGENTS.md` 仍仅角色正文。复制、冲突、提示词重新生成、字段字节核对、切换、回读、全部接收端验收、旧会话留存、恢复与授权按 `luno-core/references/sync.md`〔分支 sync-host〕。
- 宿主端经验日志只按日写：它是经核实的持久私有目录 `<安装根>/.luno/memory/` 下按 Asia/Shanghai 本地日期命名的 `YYYY-MM-DD.md`，确切路径以明确配置为准。启用开关是部署时在该目录内由获准部署者设置的常规非软链文件 `.daily-memory-enabled`，启用值为单行 `enabled` 加一个 LF；新会话读取它判断是否已启用，它只决定能否写，不授予访问或写入权，本条规则不创建或修改任何现场文件。开关缺失、格式或权限异常、缺少取值，或路径无法核实时，停止相关写入，不猜测启用与否，也不回退到其他日志文件。公开规则已部署、日期文件或目录已存在、其他会话的转述，都不能证明已启用或已有写入授权；启用也不代替授权。只有确有符合收录条件的可复用经验且有适用的写入授权时才写；遇到记忆关闭、无写权或路径和归属不清时停止相关写入。维护和回读按 `references/memory-common.md`〔分支 maintenance〕。
- 用户已授权其指定的既有 Paseo 宿主的 LUNO 主会话，对该宿主已确认的私有按日经验日志主动追加：该主会话在真实任务收尾自行判断本次是否有新增、经核实且可复用的经验，命中就按既有串行末尾追加和写后回读写入；同一部署的后续 LUNO 主会话读取本节即沿用，无需逐次确认。未命中、不符合 `references/memory-common.md`〔分支 maintenance〕 收录条件或授权已撤销时不写，也不扫描历史或补录。该约定只覆盖该部署的 LUNO 主会话（含该宿主 Paseo 启动的 Claude Code 主会话；不含手工运行的原生 CLI、角色子会话及 LENS/FORGE）和该宿主已确认的按日日志，不构成其他使用者、安装、原生 CLI 或角色子会话的授权。写入由该主会话自身完成，不交派发的子会话代写。经验日志只记录已发生的授权，不作新的授权来源，也不作为首次检索或访问的依据。
- 私有目录由获准部署者准备，任务会话不创建或修复该目录；目录缺失或不可写时报入口缺失并停止相关写入，不据此回退到其他文件。每个新任务的首次写入按 Asia/Shanghai 本地日期选择 `YYYY-MM-DD.md`：该文件经核实是同一私有目录内的常规文件就追加，不存在就排他创建。创建前确认目标路径不是软链、未被其他对象占用；常规文件以排他方式新建并设为 600。新建和后续打开都确认作用于写前核实的同一实际路径，不跟随软链替换，也不把重名的目录或其他对象当成日志文件。跨午夜的中断恢复或补齐仍回原文件，不因日期变化另建；后续新任务才按当时日期重新选择。
- 同一实际日志位置优先由一名已获准的写入者串行处理。有多名写入者时，先用现有协作方式确认写入顺序。从最终写前复核到写后回读，须能确认正在写入的日志没有并发写入，否则暂停冲突写入。协调该私有目录和当日文件，首次创建当日文件也在该串行条件下完成，排他创建成功不能代替写者协调。写前重核路径身份、归属、权限和末尾状态，并按维护规则检查内容、秘密和已知重复。先前的检索与本次查重都不能代替写者协调。对既有文件，以不创建、不截断的追加方式打开文件，确认打开对象与写前核实的文件相同后再在末尾写入完整条目。保留原字节和条目边界，禁止覆盖或整份重写。
- 按写前核实的末尾位置回读实际新增，核对条目边界、预期内容和新增次数，按维护规则实测字节和物理行数。写入失败、中断或回包不明时，先确认原写入已停止，在串行条件下核实同一文件从原末尾位置到当前末尾的实际字节。已完整写入只做回读，证实未写入才按写前流程重试。若能确认从原末尾到当前末尾仅有本次拟写内容的逐字节前缀，只在原授权仍有效时补齐余量并回读。仍无法核清结果或需要其他修复时，暂停冲突写入并交回，按既有维护规则及授权处置。
- 原生 LUNO 主会话与 Paseo 的 LUNO 主会话只有在明确获准（原生 CLI 需独立授权）、且核实使用同一个实际位置时共用日志；Paseo 启动的 Claude Code LUNO 主会话与 Codex 的 LUNO 主会话适用同一条件（须明确获准且核实同一实际位置）：须共同使用同一私有目录并核对当日文件。优先采用明确配置的私有路径。涉及容器时核对挂载映射，目录同名也须确认是同一位置。运行用户、安装根或挂载变化后重核。`CODEX_HOME` 及角色配置目录用于定位各自的配置，不能据此推定共享日志的位置或访问范围。
- 经验日志按需检索，不自动注入。按关键词在该私有目录内符合 `YYYY-MM-DD.md` 的常规文件中检索，不跟随软链，只回读命中的相关条目及其条件。安装器不创建这些文件；主会话共用日志的约定不授予角色子会话访问权。只在获准的真实任务中，由另一独立主会话按已核路径和关键词定位已有真实经验并回读相关记录及其适用条件，核验跨会话检索。没有该场景时仅报未验证，禁止为验证写入条目。
- Codex 的 memories 与 Claude Code 的自动记忆都不作为 LUNO 记忆：不往里写，也不据此采用经验。

## Surge 控制目标

本端没有默认控制目标，也不设置 `SURGE_ALLOW_REMOTE`。Surge 任务在本端只做配置、规则和模块的离线工作；需要操作实例时交回 Minis 端，或由用户为当次任务显式指定可达目标并单独授权。
