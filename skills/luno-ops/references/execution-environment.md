# 执行环境选址（Minis 端）

本端有两个 Linux 执行面：本机 **iSH**（Alpine/aarch64，与 `/var/minis/*`、`apple-*`、`minis-*` 同侧）和远端的 **OnlyBoxes 沙箱**（x86_64，经已配置的 MCP 调用）。下面的判据按顺序过滤，前一步不过就停；它只给选址依据，不授予使用沙箱的权限。

1. **准入（硬约束）**：沙箱不是安全隔离区。2026-10-18 对 0.14.1 的取证显示：容器内是 UID 0 加 Docker 默认能力集，磁盘没有配额（可以写满宿主根分区）；worker 持有 `/var/run/docker.sock`（经 Docker API 可以到达宿主 root），并用 host 网络（可以直连宿主 `127.0.0.1` 上的服务）。这些风险没有解除，所以：
   - 只承接准入通过的任务：来源和版本可追溯，入口和依赖的执行行为已核对，没有未经审查的动态下载和执行；**助手或模型生成的代码同样要核对，核不了就不准入**。
   - 不承接不可信代码和来源不明的脚本或二进制，不承载秘密、生产凭据和生产数据；**默认不访问宿主和私网服务**，公网只限任务必需的目标，禁止扫描、洪泛和代理转发。本机侧对这类代码只做只读静态检查，运行它要先有独立的隔离环境。
2. **归属**：区分执行时必须直接访问的本机能力和最终交付的位置；硬约束淘汰的是候选环境，不是任务本身。
   - **默认沙箱**（通过第 1、3、4 步就派，不因本机也能做或更熟悉而改判；结果在授权内回传本机）：纯计算，统计和数据处理，媒体转码，文档转换，x86_64 wheel 和需要 glibc 行为的任务，gcc/g++/make 编译和小型构建，批量文本、正则、日志解析，JSON/CSV/SQLite/zip 转换。
   - **混合**（本机取数、编排、落盘，远端计算）：本机源文件的批处理，可以断点续跑的长任务（分段派发、逐段回传），公共 HTTP 抓取和解析。
   - **保持本机**：要读写 `/var/minis/*` 或要用 `apple-*`、`minis-*`、记忆、已有浏览器会话的子任务；规则仓库的测试（`TMPDIR` 不指向 Minis 共享目录）；秘密、生产凭据或生产数据；不可信代码；宿主和私网探测；目标服务器的真实状态和服务操作（走既有的 SSH 授权通道）。
   - **不迁移**：毫秒级的小操作；超过已核上界或上界不明的任务；无法完整校验回传的大产物；要求 Alpine/musl、aarch64 或与生产目标完全同构的验收。
   - **`computerUse` 和 `CU:<worker_id>` 路径一律不用**：它们路由到 worker-sys，在宿主上以 `/bin/sh -lc` 直接执行、没有容器隔离。本账号现在没有 worker-sys，但新增 worker-sys 或路由改变后路径就会恢复；工具列出来不等于可以调用，没列出也不能断言服务端没有这个能力。
3. **资源**：任务要给出运行时长，以及磁盘、日志、解压、缓存和并发的上界，并逐项不超过派发前在当次已授权环境实测、适用于当前版本和镜像的 vCPU、内存、pids、磁盘和回传界限。仓库不保存这些现值：历史的限额、镜像能力和耗时都不当作现值，有限的测量不外推，版本或镜像变化后整体重核。给不出上界、没取得当次界限，或会并发压满宿主的，不派沙箱；不用压测或试跑整个任务来取得准入。
4. **交付完整性**：结果必须完整回传，并通过适用的校验（长度、序号、总长、哈希、解码等）；截断、缺块、目标不完整或校验失败都不算交付。工具或协议报错、执行状态不明、lease 到期，都按结果未知处理：不盲目重试，不跨协议重跑。
5. **成本**：前四步都通过后才比较成本。耗时未知就标未知，不为了定路由先跑一遍完整任务；只有批量化这类有依据的复用才计入比较。
6. **未知或失败**：不擅自换环境。OnlyBoxes 不可用、能力未核或结果未知时，报告证据，停止依赖这个结果，按能力降级或暂停；**不静默改由 iSH 承接重计算。**

# OnlyBoxes 沙箱调用（Minis 端）

本资源讲已经选定沙箱之后的调用、会话、依赖和回传；选址、准入和资源上界按 `references/execution-environment.md`〔分支 execution-environment〕。

## 接口与成功判据

- **接口**：工具参数和返回形态查官方 [MCP Tools Reference](https://onlybox.es/en/docs/mcp-tools/)，REST Task 查 [Console API Reference](https://onlybox.es/en/docs/console-api/)。文档不证明当前实例的版本、账号能力或工具实际可调用：调用前以 `tools/list` 返回的实际定义为准，不猜工具名、参数、认证或未列出的端点。官方说明被隐藏的工具仍能按名调用，所以工具列表里有没有某个工具都不构成访问控制结论。
- **成功判据**：MCP 协议错误、工具结果的 `isError: true` 和正常输出分开记录；出现前两者时，不把其他字段当成功。执行类工具另核 `exit_code`、`stderr` 和截断标志（如果返回）。只有协议和工具结果都没有错误、`exit_code=0`、目标通过完整性校验，才算执行成功；非零 `exit_code` 是执行失败的结果，仍要保留并回传 `stderr`。
- **认证**只用已配置连接承接的变量引用（`ONLYBOXES_API_KEY`），不回显、不转存，也不把秘密传给沙箱里的代码。

## 本端实测（2026-11-05，Minis 1.16 (21)，合成样本）

- `terminalExec` 在同一 `session_id` 下保留文件和 cwd，但 `export` 不跨调用保留（官方说会保留环境变量，与实测不符）：命令仍用绝对路径，需要的变量和别名在同一次调用里设置。
- `pythonExec` 抛异常时返回 `exit_code=1`，traceback 在 `stderr`。MCP 的 Python 结果没有 REST Task 的 `status`：不伪造状态，也不改用 Task 轮询来判定 MCP 调用。
- `readImage` 返回 base64 图像：解码后核对 MIME、字节长度或哈希、能否解码，再做本机的视觉读取；只拿到 `file_path`、`size_bytes` 等元数据不算读图成功。
- 未验证：新会话、截断阈值、超时、lease 到期、并发和 REST Task 的现行为。

## REST Task（长任务）

- 只在需要长任务追踪或恢复、并且本次授权明确允许 REST 时用；短调用不因为 MCP 结果不方便就跨协议重跑。
- 2026-11-01 实测（实例版本未知）：`mode=async` 返回 `task_id` 和同源的 `status_url`，用相同认证查询。要设客户端超时和总轮询预算；提交时遇到 HTTP 502/504 或查询失败，有 ID 就先在预算内查询，没有 ID 或查不到终态都按结果未知处理，不盲目重试。
- 成功要同时满足 `status=succeeded` 和 `exit_code=0`，并核对 `result.output`、`result.stderr` 和目标完整性。每个新 Task 用唯一的 `request_id`，文档里的幂等不作为重试的保证；关闭或 404 不证明容器已经回收。

## 依赖与回传

- 准备依赖前，核对来源、版本、行为和安装边界；未经审查的动态下载不准入。`pythonExec` 的第三方依赖按官方说明用 PEP 723 脚本元数据声明，本端还没验证过安装效果：不凭耗时或安装器输出推定成功，保留 `exit_code` 和 `stderr`，并用同一个解释器核对导入结果。
- 需要分块回传时，记录序号、总长和整件 SHA-256，逐块和整件都校验后再落盘；拿不到可验证的完整目标就不交付。
