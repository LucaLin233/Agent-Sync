# CFST 测速（Minis 本机）

固定用法和脚本由用户 2026-10-30 指定。脚本行为于 2026-11-28 在 Minis/iSH 上按 `/var/minis/shared/cfst/cfst-run.sh` 的原文静态核对；没有运行新版脚本，也没有验证联网、物理直连或真实恢复。过去按旧参数做过的实测不能当作新版的实测，旧日期也不构成新版参数的授权。

## 前提

- 只在 **Minis 本机（iSH）** 执行：测速流量要走 iOS 直连，需要临时让指定网段绕过 Surge VIF，其他端不适用。
- 三项同时成立才执行，**缺任何一项就停下报告**，不自行改脚本、模块或网段：脚本 `/var/minis/shared/cfst/cfst-run.sh` 可读可执行，同目录的 `cfst`（arm64）可执行、`ip.txt` 可读，脚本目录可写（结果文件写在这里）；模块「CFST 测速直连」（同目录 `CFST.sgmodule`）在 `surge-cli module list` 里可见。
- 认证只走 `/usr/local/bin/surge-cli` 和同机 Controller，`SURGE_API_KEY` 已注入（缺了脚本直接退出）；密码经 stdin 传入，不进命令行、不落盘、不打印。测速和探测等普通进程用最小环境，不继承这个凭据。
- **每次执行都要另核授权**：测速占用带宽或蜂窝流量，并且脚本会自行启停 Surge 模块。改变模块状态会安排 profile reload，reload 通常差量应用，必要时会自动转成完整重启，可能让连接、VPN 或隧道重连、短暂断网；模块自述的「测完关闭并重连 VPN」不是自动恢复的保证。直接或间接 reload 前先核本次变更与实例版本；无法排除完整重启时，即使整批已获批准，也要就断连接、清缓存和临时规则以及 VPN/隧道影响再次单独确认，未获准不运行。确认按 `luno-surge` 入口〈安全与平台边界〉和 `luno-core/references/execution.md`〔分支 safety〕〈授权与安全〉执行，不把重新测速当作默认的验收手段。
- 执行前按 `luno-surge` 入口〈引擎状态预检〉核对引擎、VPN 和 Suspend 状态；模块状态一致或测速结果都不能代替这项核对。
- 调用前核对实际的二进制版本、参数和模块网段覆盖；替换二进制后重核。

## 运行

```sh
/var/minis/shared/cfst/cfst-run.sh              # 输出 result-MMDD-HHMM.csv
/var/minis/shared/cfst/cfst-run.sh my.csv       # 位置参数指定输出文件名
CFST_OUT=my.csv /var/minis/shared/cfst/cfst-run.sh
```

位置参数优先于 `CFST_OUT`。目标名被占用时在 `.csv` 扩展名前加 `-2`…`-50`（非 `.csv` 直接加后缀），不覆盖已有文件；找不到可用名或目录写不进去按错误退出（`1`）。

固定参数（脚本内固定参数，用户指定，不要改脚本或手工替换）：

- 阶段1 只测延迟，不下载：200 并发 TCPing，延迟窗口 40–300 ms，硬预算 300 秒。脚本按结果 CSV 的原序（丢包优先、再按延迟）去重，取落在 `ip.txt` 网段内的最多 20 个有效 IPv4 作候选。
- 阶段2 复筛下载：对候选**先重新做一轮 TCPing 的延迟/丢包复筛，再对复筛结果下载**，每个 IP 至多 15 秒，≥20 MB/s 记一条达标，3 条达标即停，硬预算 350 秒，沿用原 Debian ISO 地址。
- 三个数不是一回事：输入候选至多 20 个；实际尝试数受复筛淘汰、3 条提前停和预算影响；达标数只数 ≥20 MB/s 的结果行。结果 CSV 的平均延迟是阶段2 TCPing 的量，不是下载耗时。

## 脚本行为

1. 读取模块原状态（`[x]`/`[ ]`）；读不到或模块不存在就退出，此时还没建临时目录，也没有自动恢复动作。
2. 原状态关闭才临时启用、等 3 秒并回读为 `on` 才继续，回读不是 `on` 就中止；原本开着的全程不切换，结束时也不关。
3. **绕过启发式检查**：从 `ip.txt` 每个 IPv4 网段的基址取 +2、+3，用 `curl -sk -w '%{time_connect}' https://<ip>/` 测 443 上的 TCP 握手时间（TLS 完成之前的建连，不是 TLS 握手耗时）。每满 8 个候选汇总一批，累计每个正计时（>0）并按毫秒截整：任一批出现 **≥ 20 ms** 就放行继续测速；否则累计成功 **≥ 2** 个时按启发式怀疑仍被 VIF 接管并中止；累计不足 2 个时无结论并中止。累计数是汇总次数，**不等于不同 IP 数**；末尾不足 8 个的一批不汇总，所以可能以无结论结束。20 ms 是受机房、路由和首包放行影响的固定启发值，不能证明已直连或仍被 VIF 接管，也不是已物理直连的证明；没有独立路径证据时，只报告该启发式结果，不宣称绕过已核验。
4. **阶段1 延迟筛选**：按上面的参数只测延迟，不下载；没有候选时不进入下载阶段，不生成 CSV。
5. **阶段2 复筛下载**：先复筛、再下载，按上面的参数和 3 条即停执行。
6. **结果发布**：只有两个阶段都正常完成并成功写出结果文件时才生成最终 CSV；失败或超时不发布阶段临时结果，临时文件随私有临时目录清理。达标 1–2 条照常保留，0 条不新建。
7. 有界执行与恢复：两阶段都用轮询代替阻塞的 `wait`（ash 会推迟 trap，阻塞时 INT/TERM 无法及时恢复）；超时先 TERM，等至多 5 秒再尝试 KILL。只有在已读到模块原状态并注册 `EXIT`/`INT`/`TERM`/`HUP` 的 trap 之后，才自动尝试恢复：终止 cfst、原状态为 `off` 时执行关闭、再回读模块状态并打印。外层包装（超时、调度）要把开模块等待、绕过核验和恢复本身算在阶段预算之外，留出恢复时间。

## 判读与恢复

- 结果默认是脚本同目录的 `result-MMDD-HHMM.csv`，脚本最后打印表头加前三条数据；延迟、丢包和下载速度以 cfst 输出为准。单次结果只代表当次的网络和出口，不据此下长期结论。
- 退出码：`0` 达标 ≥3；`4` 达标 1–2（已保留）；`30` 无达标，含阶段1 空筛选（没有候选、无需下载）；`10` 阶段1 失败；`11` 阶段1 超时（300 秒）；`20` 阶段2 失败；`21` 阶段2 超时（350 秒）；`1` 前置检查、模块状态、绕过核验或结果落位错误；`40` 模块状态恢复失败。
- `40` 只在关闭模块的命令失败、或恢复后回读不等于原状态时出现，并且只把原本会以 `0` 结束的结果改成 `40`；已经发布的 CSV 不撤回，其他非零退出码也不会被 `40` 替代。所以任何退出码之后都要看脚本打印的恢复回读，不能只凭退出码判断模块是否已恢复。
- 出现 `40`、没有恢复回读、回读与原状态不符，或被 `SIGKILL`（trap 不执行，模块可能还开着）时，人工核对 `surge-cli module list`；原状态不明先核实，不猜。人工启停模块沿用当次授权和上面的 reload 门禁；模块状态恢复一致不等于 VPN 或连接已恢复。
- 中断后残留的临时目录按实际路径核查。
