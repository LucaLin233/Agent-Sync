# CFST 测速（Minis 本机）

固定用法和脚本由用户 2026-10-30 指定；下面的两阶段参数与判读是 2026-11-28 按脚本原文静态核对的结果，没有实际执行过测速，也没有验证过新版脚本的真实联网行为或物理直连。

## 前提

- 只在 **Minis 本机（iSH）** 执行：测速流量要走 iOS 直连，需要临时让指定网段绕过 Surge VIF，其他端不适用。
- 三项同时成立才执行，**缺任何一项就停下报告**，不自行改脚本、模块或网段：脚本 `/var/minis/shared/cfst/cfst-run.sh` 可读可执行；同目录有 `cfst`（arm64）和 `ip.txt`；模块「CFST 测速直连」（同目录 `CFST.sgmodule`）在 `surge-cli module list` 里可见。
- `surge-cli`、`curl` 在 PATH 里，`SURGE_API_KEY` 已注入（缺了脚本直接退出）；密码只经 stdin 交给同机 Controller，不进命令行、不落盘、不打印。
- **每次执行都要另核授权**：测速占用带宽或蜂窝流量，并且脚本会自行启停 Surge 模块。改变模块状态会安排 profile reload，reload 通常差量应用，必要时会自动转成完整重启，可能让连接、VPN 或隧道重连、短暂断网；模块自述的「测完关闭并重连 VPN」不是自动恢复的保证。执行前按 `luno-surge` 入口〈安全与平台边界〉就这些影响单独确认，再按 `luno-core/references/execution.md`〔分支 safety〕〈授权与安全〉确认当次授权，不把重新测速当作默认的验收手段。
- 执行前按 `luno-surge` 入口〈引擎状态预检〉核对引擎、VPN 和 Suspend 状态；测速结果和模块状态都不能代替这项核对。
- 调用前核对实际的二进制版本、参数和模块网段覆盖；替换二进制后重核。

## 运行

```sh
/var/minis/shared/cfst/cfst-run.sh              # 输出 result-MMDD-HHMM.csv
/var/minis/shared/cfst/cfst-run.sh my.csv       # 位置参数指定输出文件名
CFST_OUT=my.csv /var/minis/shared/cfst/cfst-run.sh
```

固定参数（用户指定，写在脚本里，不要改脚本或手工替换）：

- 阶段1 只测延迟，不下载：`cfst -n 200 -tll 40 -tl 300 -dd -p 0`，200 并发 TCPing，延迟窗口 40–300 ms，按该版默认丢包筛选与探测次数。
- 阶段2 复筛下载：`cfst -n 200 -tll 40 -tl 300 -dn 3 -sl 20 -dt 15 -p 3 -url https://dl.yuumi.moe/iso/debian-amd64.iso`，沿用同一个 Debian ISO 地址，每个 IP 至多 15 秒，≥20 MB/s 记一条达标，3 条达标即停。

## 脚本行为

1. 读取模块原状态（`[x]`/`[ ]`）；读不到或模块不存在就退出，此时还没建临时目录。
2. 原状态关闭才临时启用并等 3 秒；原本开着的全程不动，结束时也不关。
3. **绕过启发式检查**：从 `ip.txt` 每个 IPv4 网段的基址取 +2、+3，分批用 `curl -sk -w '%{time_connect}' https://<ip>/` 测 443 的 TCP 握手时间（不是 TLS 完成时间）。有一个候选 **≥ 20 ms** 时，脚本按启发式放行继续测速；全部 < 20 ms 且成功 **≥ 2** 个时，脚本按启发式怀疑仍被 VIF 接管并中止；其余（成功 0 或 1 个且没有高值）无结论并中止，成功 1 个也走这里。20 ms 是受机房、路由和首包放行影响的固定启发值，不能证明已直连或仍被 VIF 接管；没有独立路径证据时，只报告该启发式结果，不宣称绕过已核验。
4. **阶段1 延迟筛选**：硬预算 300 秒，结果只含延迟，不含下载。脚本按结果 CSV 的原序去重，取落在 `ip.txt` 网段内的最多 20 个有效 IPv4 作候选。没有候选时不进入下载阶段，不生成 CSV。
5. **阶段2 复筛下载**：硬预算 350 秒，对阶段1 的候选队列逐个下载复筛，队列上限 20 个；实际尝试数受预算限制，与达标数不是同一口径，达标数只数 ≥20 MB/s 的结果行。3 条达标即停，不足则把已达标项写进结果。
6. 有界执行与恢复：两阶段都用轮询代替阻塞的 `wait`（ash 会推迟 trap，阻塞时 INT/TERM 无法及时恢复）；超时先 TERM，5 秒后 KILL。`EXIT`/`INT`/`TERM`/`HUP` 都走恢复：终止 cfst、按原状态关闭模块、回读并打印模块状态，`mktemp -d` 建的临时目录在结束时清理。外层包装（超时、调度）要把开模块等待、绕过核验和恢复本身算在阶段预算之外，留出恢复时间。

## 判读与恢复

- 结果默认是脚本同目录的 `result-MMDD-HHMM.csv`，脚本最后打印表头加前三条数据；延迟、丢包和下载速度以 cfst 输出为准，下载延迟是 TCPing 口径，不是 HTTPing 延迟。单次结果只代表当次的网络和出口，不据此下长期结论。
- 目标文件已存在时自动改用 `<名称>-2.csv`、`-3.csv`…，不覆盖已有结果。
- 达标 1–2 条时照常写结果文件并保留这些达标项，不足 3 不是失败；0 条达标不新建 CSV，阶段1 没有候选同样不新建，此时没有可保留的结果。
- 退出码：`0` 达标 ≥3；`4` 达标 1–2（已保留）；`30` 无达标，含阶段1 空筛选（没有候选、无需下载）；`10` 阶段1 失败；`11` 阶段1 超时（300 秒）；`20` 阶段2 失败；`21` 阶段2 超时（350 秒）；`1` 前置检查、模块状态或绕过核验错误；`40` 模块状态恢复失败，须人工核对。
- `40` 只替换原本会以 `0` 结束的结果，其他非零退出码保持原值；所以任何退出码之后都要看脚本打印的恢复回读，不能只凭退出码判断模块是否已恢复。
- **被 `SIGKILL` 时 trap 不会执行**，模块可能还开着；原状态读不到时脚本虽在启用前退出，也不能假定没动过。两种情况都人工核对 `surge-cli module list`，按原状态处置（原来关闭就关掉，原状态不明先核实，不猜），不因为「跑完了」就假定已恢复。中断后残留的临时目录按实际路径核查。
