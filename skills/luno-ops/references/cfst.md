# CFST 测速（Minis 本机）

先取得本包入口必需规则。

来源：用户 2026-10-30 指定的固定用法与脚本；以下脚本行为据 2026-10-31 静态核对，未执行测速。

## 适用与边界

- 仅在 **Minis 本机（iSH）** 执行：测速流量走 iOS 直连，需临时让指定网段绕过 Surge VIF，其余端不适用。
- 前置三件必须同时成立：脚本 `/var/minis/shared/cfst/cfst-run.sh` 可读可执行、同目录 `cfst`（arm64）与 `ip.txt` 存在、模块 `CFST 测速直连`（同目录 `CFST.sgmodule`）在 `surge-cli module list` 中可见。**缺任一项即停**，不自行改脚本、不改模块、不加网段。
- 环境：`surge-cli`、`curl` 在 PATH；`SURGE_API_KEY` 已注入（脚本缺它直接退出）。凭据只引用变量，不打印、不入命令行、不写文件。
- **执行另核授权**：测速占带宽/蜂窝流量并临时改 Surge 模块状态（TUN 重配），启停模块可能使 VPN/隧道重连及短断；模块自述「仅测速时启用，测完关闭并重连 VPN」不是自动恢复保证。按 `luno-core/SKILL.md`〈授权与安全〉当次确认；不把重新测速当默认验收。

## 运行

```sh
/var/minis/shared/cfst/cfst-run.sh              # 输出 result-MMDD-HHMM.csv
/var/minis/shared/cfst/cfst-run.sh my.csv       # 位置参数覆盖输出名
CFST_OUT=my.csv /var/minis/shared/cfst/cfst-run.sh
```

脚本行为（静态核对，2026-10-31）：

1. 读模块原状态（`[x]`/`[ ]` 标记）；读不到或模块不存在即退（`die`，退出前不建临时目录）。
2. 原状态为 `off` 才临时启用并等 3 s 稳定；原本已开则不动，结束时也不关。
3. **绕过核验**：从 `ip.txt` 各 IPv4 网段基址取 +2、+3，分批 `curl -sk -w '%{time_connect}' https://<ip>/` 测到 443 的 TCP 握手时间，不是 TLS 完成时间或应用层往返。脚本按高值优先：任一候选 **≥ 20 ms** 即判「已直连」（成功 1 个亦然）；全部 < 20 ms 且成功 **≥ 2** 个判「仍被 VIF 接管」并中止；无高值且成功 **< 2** 个（含 0、1 个）判「无结论」并中止。20 ms 是受机房、路由和首包放行影响的固定启发式，不是通用协议判据。
4. 跑固定参数（见下），轮询而非阻塞 `wait`（ash 会推迟 trap，导致 INT/TERM 不能及时恢复）。
5. `EXIT`/`INT`/`TERM`/`HUP` 统一走恢复：先终止 cfst（TERM→5 s→KILL），再按原状态关闭模块，并打印恢复后状态。

固定参数（用户指定，勿改）：

```sh
./cfst -httping -cfcolo LAX,SJC -url https://dl.yuumi.moe/iso/debian-amd64.iso \
  -n 200 -dn 3 -dt 15 -tl 400 -sl 20 -p 3 -o "$OUT"
```

`-httping` 走 HTTPing 口径（不是 TCPing）；`-tl 400` 是该口径下的延迟上限，2026-10-30 本机观察为「HTTPing 比 TCPing 高约 100–150 ms，`-tl 300` 会清零」，该观察只作本机经验、不外推为普遍规律；`-cfcolo LAX,SJC` 固定两机房；`-n 200 -dn 3 -dt 15 -sl 20 -p 3` 为固定采样与并发。

## 判读

- 结果文件默认落在脚本同目录 `result-MMDD-HHMM.csv`，脚本末尾打印前 3 行；延迟、丢包与下载速度口径按 cfst 自身输出，不把 HTTPing 延迟当 TCP 建连延迟。
- 中止分报：模块不可读/不存在；VIF 仍接管；绕过核验无结论。分支以〈运行〉第 3 步高值与成功数为准，不按提示推断「全部失败」：无结论文案写「候选地址均未建连成功（成功 N 个）」，但一个成功且 `< 20 ms` 也会进入该分支。
- 「跑完」不等于「可用」：结果是否代表当前线路须结合当次网络与出口判断；不对单次结果下长期结论。

## 恢复与未验证

- **恢复语义**：原 `off` 时退出/中断关闭模块；原 `on` 全程不动、不替它关闭。原态读不到时脚本在启用前 `die`，仍先人工核 `surge-cli module list`，不假定没动过。
- **`SIGKILL` 后 trap 不执行**：模块可能仍启用，人工核 `surge-cli module list` 并按原态处置（原 `off` 则关闭；原态不明先核实，不猜），不因跑完假定已恢复。
- 更长任务的后台表现未验证，不作运行时长保证。脚本内部用 `mktemp -d` 在临时目录做核验文件、结束时清理；中断后若残留属异常，按实际路径核查。
- 调用前核实际二进制版本、参数及模块网段覆盖；升级替换二进制前须重核网段覆盖与参数是否仍受支持。
