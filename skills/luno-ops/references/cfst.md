# CFST 测速（Minis 本机）

固定用法和脚本由用户 2026-10-30 指定；下面的脚本行为是 2026-10-31 静态核对的结果，没有实际执行测速。

## 适用与前提

- 只在 **Minis 本机（iSH）** 执行：测速流量要走 iOS 直连，需要临时让指定网段绕过 Surge VIF，其他端不适用。
- 三个前提必须同时成立：脚本 `/var/minis/shared/cfst/cfst-run.sh` 可读可执行；同目录有 `cfst`（arm64）和 `ip.txt`；模块「CFST 测速直连」（同目录 `CFST.sgmodule`）在 `surge-cli module list` 里可见。**缺任何一项就停**，不自行改脚本、模块或网段。
- 环境：`surge-cli`、`curl` 在 PATH 里，`SURGE_API_KEY` 已注入（缺了脚本会直接退出）。凭据只引用变量，不打印、不进命令行、不写文件。
- **执行要另核授权**：测速占用带宽或蜂窝流量，并临时改变 Surge 模块状态（TUN 重配），启停模块可能导致 VPN 或隧道重连、短暂断网；模块自述的「测完关闭并重连 VPN」不是自动恢复的保证。按 `luno-core/references/execution.md`〔分支 safety〕〈授权与安全〉当次确认，不把重新测速当作默认的验收手段。

## 运行

```sh
/var/minis/shared/cfst/cfst-run.sh              # 输出 result-MMDD-HHMM.csv
/var/minis/shared/cfst/cfst-run.sh my.csv       # 位置参数指定输出文件名
CFST_OUT=my.csv /var/minis/shared/cfst/cfst-run.sh
```

脚本行为：

1. 读取模块原状态（`[x]`/`[ ]`）；读不到或模块不存在就退出（退出前不建临时目录）。
2. 原状态是关闭才临时启用，并等 3 秒稳定；原本开着的不动，结束时也不关。
3. **绕过核验**：从 `ip.txt` 每个 IPv4 网段的基址取 +2、+3，分批用 `curl -sk -w '%{time_connect}' https://<ip>/` 测 443 端口的 TCP 握手时间（不是 TLS 完成时间，也不是应用层往返）。只要有一个候选 **≥ 20 ms** 就判定「已直连」；全部 < 20 ms 且成功 **≥ 2** 个，判定「仍被 VIF 接管」并中止；没有高值且成功不足 2 个（0 或 1 个），判定「无结论」并中止。20 ms 是受机房、路由和首包放行影响的固定启发值，不是通用判据。
4. 用固定参数运行 cfst，用轮询而不是阻塞的 `wait`（ash 会推迟 trap，阻塞时 INT/TERM 无法及时恢复）。
5. `EXIT`/`INT`/`TERM`/`HUP` 都走恢复：先终止 cfst（TERM → 5 秒 → KILL），再按原状态关闭模块，并打印恢复后的状态。

固定参数（用户指定，不要改）：

```sh
./cfst -httping -cfcolo LAX,SJC -url https://dl.yuumi.moe/iso/debian-amd64.iso \
  -n 200 -dn 3 -dt 15 -tl 400 -sl 20 -p 3 -o "$OUT"
```

`-httping` 是 HTTPing 口径（不是 TCPing），`-tl 400` 是这个口径下的延迟上限：2026-10-30 本机观察到 HTTPing 比 TCPing 高约 100–150 ms，`-tl 300` 会把结果清零；这只是本机经验，不推广为普遍规律。

## 判读

- 结果默认落在脚本同目录的 `result-MMDD-HHMM.csv`，脚本最后打印前 3 行；延迟、丢包和下载速度的口径以 cfst 自身输出为准，不把 HTTPing 延迟当成 TCP 建连延迟。
- 中止有三种：模块不可读或不存在；仍被 VIF 接管；绕过核验无结论。分支以第 3 步的高值和成功数为准，不按提示文字推断：「无结论」的提示是「候选地址均未建连成功（成功 N 个）」，但成功 1 个且 < 20 ms 也会进这个分支。
- 跑完不等于可用：结果是否代表当前线路，要结合当次的网络和出口判断，不对单次结果下长期结论。

## 恢复

- 原状态关闭的，退出或中断时关闭模块；原状态开启的，全程不动、也不替它关闭。原状态读不到时脚本会在启用前退出，但仍要人工核对 `surge-cli module list`，不假定没动过。
- **被 `SIGKILL` 时 trap 不会执行**：模块可能还开着，要人工核对 `surge-cli module list` 并按原状态处置（原来关闭就关掉；原状态不明先核实，不猜），不因为「跑完了」就假定已恢复。
- 脚本内部用 `mktemp -d` 存放核验文件并在结束时清理；中断后如有残留属异常，按实际路径核查。更长时间的后台运行没有验证过，不保证运行时长。
- 调用前核对实际的二进制版本、参数和模块网段覆盖；升级替换二进制前，要重核网段覆盖和参数是否仍受支持。
