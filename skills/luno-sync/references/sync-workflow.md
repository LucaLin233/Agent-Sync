使用前须取得本包入口的范围/通用方法/安全/测试/输出规则；跨项依入口取必需规则并集，加载不授权。

## 轻量同步顺序

规则或提示词正文的改动，须先提交可定位的对象与基线、逐字改稿、验证与回滚方案，经独立审查（默认 LENS）明确判为「通过」并由负责人核验采纳后，才可修改候选交付物；实施差分须另行独立验收，小改亦不豁免上述两阶段。审查独立性、通道溯源、结论与降级依 `luno-review`〈审查执行〉及〈输出〉；本条是正文改动的前置要求，不因该任务原属单纯修改而免审。仅同步已经审查、验收通过且内容未变的版本，不重复开审查轮次；版本变化或新增证据、范围变化、结论疑点按该规则处理。

**独立副本/分支修改 → 必要校验 → GitHub 原生 PR → 串行合并 → 备份将覆盖的对象 → 按合并变化同步 → 逐端回读。** 不使用自研发布状态机、冻结链、摘要账本、档案窄提交或机器证据回执；不要求每次正文同步跑全仓重测试或全端巡检。

1. 每会话用独立 clone 和唯一任务分支，Minis 候选落 `/var/minis/shared/agent-sync-candidates/<会话标识>/`，不放 `workspace/`、不用共享 `.git` 的 worktree。一份副本只允许一个写入者；各会话只推自己的分支/PR，不直接推 main、不写共享集成副本。由当前任务负责人指定的收口者逐个合并，并串行部署同一生效对象；独立副本避免编辑互踩，原生 PR 承载差分与合并冲突，不声称自动解决语义冲突或平台竞态。
2. 先读本批 diff 和 `PENDING.md`，核授权、变化对象及其登记落点。只执行变更路径命中的必要测试（真源 `tests/run-tests.sh` 与其选路出口）；纯正文运行 `smoke`，不默认加跑全部工具专项。`tools/sync-all.sh` 只运行结构守卫与包内校验，不读生效端；rc=1／3 阻断，rc=2 仅提示。登记或公共工具变化时完整执行仍保留的实际消费者，不用缩跑集冒充提速。结构守卫检查加载边／资源边、单份登记内部身份、包内引用与义务块存在性，不比对正文逐字片段；正文防弱化仍依两阶段独立审查，改加载边／资源边须同批更新 `tools/rule-claims.tsv`。
3. 审阅暂存 diff，显式 `git add <本批路径>` 后普通 commit、非强推到本会话任务分支，用 `gh pr create` 开原生 PR（不是自研 PR 工具）。合并前读取最新 main；基线前进时普通 merge main 到本分支，逐处处理冲突、核无冲突内容并重跑受影响测试，不用 union/整份选边/强推。收口者确认前一个 PR 已合并后再合下一个；用户已就本仓库明确授权：批准合并即含删除该 PR 的源分支，故用 `gh pr merge --squash --delete-branch` 收口（本仓库只允许 squash 合并）、无需另行确认；合并前把 PR 内**全部提交的 Author**（及去重后的 `Co-authored-by`）写成 `Co-authored-by: 名 <邮箱>` 行放进 squash 提交说明（`--subject`／`--body` 或网页表单），身份取自 `git cat-file commit` 原始字节；署名缺失或不合规由 push 事件的检查器判违规，合并前自核一次。以 `gh api` 回读 merged 状态、main 提交（应为单父、Committer 为 GitHub web-flow 且已签名）及源分支已删除；删除仅限该 PR 自身源分支，用户声明保留时从其声明，失败如实记录，不扩大清理范围。远端再次前进则重新核差分，不盲重投。只从确认已合并的版本取变化对象部署，仓库合并不等于线上同步成功；未部署/部分成功须如实记录。共享集成副本仅收口者在干净时快进更新，其他会话不写。开 PR、合并及实际部署分别核既有授权，校验脚本不自动执行这些写入。
4. 仅同步已授权变化对象及其包内资源，按 `tools/sync-targets.json` 找目标；未登记对象先登记，不顺带修改无关端。覆盖前备份这些目标的**实际生效前态**（正文、资源及将改的元数据），保存在当批资产目录，核文件可读与内容/权限；不能拿候选副本冒充前态。不要求建立全仓恢复包或预演未改对象的恢复链。
5. 按对应平台受支持入口写入，默认同步授权及例外依本技能〈真源与落点〉；写入前核对目标实际生效值仍与本批已核基线一致，发现并发变更先停止相关对象、重核差分，需内容取舍时回到确认。LobeHub 同 identifier 更新优先保 ID；仅在无法原位更新且明确授权迁移时备份后重建，并联动来源登记。Minis 仅正文修改无需刷新登记，frontmatter/元数据变化按平台技能处理。秘密按总控规定，不进入诊断、备份清单、提交或派发材料。
6. 对**本次变化对象**在各登记落端回读：正文与资源逐字节一致，name/description 等变化字段另核；prompt 同时核生效字段与登记文件视图。不用安装成功、HTTP 200、CI 绿色或文件存在冒充一致。端间允许过渡态；失败只停止相关对象，列明哪些已同步/未同步，保留真实前态与恢复办法，不报整批完成、不盲重投。恢复写入也须在授权内。

按本批变化对象直接同步并逐端回读；不再提供全端聚合巡检或未变豁免参数。MCP 按本批授权直接核对所涉配置；URL 参数值一律不得输出，巡检仅投影参数名与工具选择状态枚举。不因普通正文同步自动扩项。未访问或未核验的端与 MCP 必须明确写「本轮未核验」，不得声称已通过。

## 记录与恢复

活动未决状态以根 `PENDING.md` 为唯一来源；新批按相关对象复检，未满足条件的写清条件/承接批次与责任人，无关项不阻塞本批。未决仅 `待条件`／`待他批`；已授权本批工作直接做完，不列为等待授权。只能等真实场景出现的被动观察（如行为验证）不列为未决、不写入 `PENDING.md`，当批条目按「未验证」披露一次即止，不续期、不跟踪。决定按「对象＋理由＋改判条件＋责任人」记入当批条目即为已决，后续批次不得复列为未决，命中改判条件才重新提出。

简记当批同步结果并记录于 PR：对象/改动、实际校验、各端同步及回读、提交/远端回读和未完成状态；PR 归档记录附未决项（仅 `待条件`／`待他批`；为归档时 `PENDING.md` 的完整快照，含本批入口复检的续期结论；`决定不做` 不列入）。候选未部署就明确写未部署，不预填成功。每批在本批 PR 合并前，将对象、改动与 PR 编号写入 `changelog/` 当天的 `YYYY-MM-DD.md`（不存在则新建，同日追加）；部署与逐端回读结果在合并后据实补记于该 PR，不为补记另开 PR 或提交；两处均不写秘密、主机名或本机路径。当前活动未完成项入 `PENDING.md`，写明对象、条件或承接批次、责任人与必要恢复指针；有正式独立审查时保存版本与脱敏结论，但不因普通同步自动新建审查轮次。归档合并前发现错误，在原分支修正并复核，不另开订正 PR；不递归生成补记提交。中断后先读工作区、远端与已改目标的实际状态，再决定接续或恢复。

## 变更纪律

改前定位源、引用方、登记与必要副本；声明改稿或副本与指定源片段同文／逐字一致时，预审与改后回读均按明确的片段边界及既定正文提取口径程序化比对 UTF-8 字节，不自行去前缀、strip 或归一换行；改后回读全部目标，报旧→新及 UTF-8 净差与实际测试集合/耗时，不拿计数当覆盖。规则真源与字段判等依本包入口；候选不等于生效值，尚未部署的规则不覆盖当前执行边界。最小改动优先净减，保留有意冗余，不借精简削弱秘密、授权、隔离与写后回读。

吸收第三方技能内容（并入既有技能后退役原对象）时，被吸收正文处须留来源标注：上游仓库@提交、日期、许可、是否精选改写与上游可取性，并同步来源登记；缺来源不称完成。主动补规则的例外须**本会话已发生、造成后果且因果已核实**，且文件**已有维护授权**；缺一仅建议交发起方，禁自行写入。巡检诊断按总控源头非秘密字段投影；完整恢复备份不作取密或交互输出途径。
