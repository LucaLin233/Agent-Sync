# LUNO｜跨端同步与巡检

## 范围
只处理**跨端规则对象**（常驻提示词、`luno-*` 与专题技能、子代理指令）在 **Minis 本地、LobeHub 平台、公开仓库 `LucaLin233/Agent-Sync`** 三处的落点、同步、巡检与漂移修复；**记忆各端自持、不互相同步**，各端写入手法见 `luno-minis` 与 `luno-lobehub`。

**管理落点：Minis/LobeHub/公开仓库；运行端：Minis/LobeHub**，不代表每个对象三处皆有。端侧存在性依 `tools/sync-targets.json`：「该端无」不判漂移，`present`≠已部署/核验通过；**当前身份、落点与必要的实际同步状态依各对象 `ends`，不在正文缓存逐项状态；部署沿革见旧私有 `LucaLin233/Agent` 的 git 历史**。对象身份仅以该单份登记为准；部署前按明确 ID 回读目标实际身份、identifier 与生效字段，核对本批已审基线，冲突即停相关对象并交负责人判定。取消自动三副本互校和同名发现后，不声称已排除额外同名对象；查询仍须当次授权，未授权拒绝执行。

**Minis 系统（内置）技能不是同步对象**：如 `skill-creator`，只在 Minis 本地，**不并入仓库、不上平台**，其「仓库无/平台无」**不判为漂移**。内置身份须有平台依据；未入库/映射只表示未受管，不要靠 App 技能页图标判断（图标差异的来源未核实）。第三方技能**未裁定**是否同步时同样不纳入受管集合，先由负责人明确范围与原因，不擅自新增落点。

## 资源与触发

路径相对技能根；命中即在操作/建议/审查/结论前完整读，跨项取并集，未变不重读，缺失/不完整/版本冲突停依赖。加载不授权。
- 规则对象或规则仓库的新增/修改/删除/恢复、工作副本/克隆/并发/发布窗口、部署/归档/巡检/同步脚本及门禁：`references/sync-workflow.md`。首次改共享真源或仓库前已读，不能到提交部署才补。
- 规则/提示词/description正文改写：另读 `references/agent-document-writing.md`；纯状态或不涉正文改写的执行不读。
- 技能新建/适配、目录/frontmatter/校验器：另读 `references/skill-authoring.md`。
- tests用例/分层登记的增改退休、准入/成本预算裁定：另读 `references/test-authoring.md`；仅执行既有测试/查状态不读。

## 真源与落点

候选在独立仓库编写，同一生效对象由当前任务负责人（主助理职能）串行同步（流程见 `references/sync-workflow.md`）；候选不等于生效值，按本批变化对象回读，仓库记录实际同步状态。

**默认同步授权**：依用户明确确认，本技能范围内所有规则对象（常驻提示词、技能及包内资源、子代理指令与配置）的已授权修改，在按 `references/sync-workflow.md` 完成按风险分级所需的独立预审、独立差分验收及必要校验后，默认按 `tools/sync-targets.json` 的登记落点完成提交、PR、合并、部署与逐端回读，不逐次征询；本条不授权自行新增修改或扩大同步范围。超出既有授权边界时仍须确认，包括新增或删除同步对象、新增端或环境、扩大权限或数据访问面、规则部署以外的生产数据变更、不可逆操作，以及跨端内容冲突需取舍；秘密面仍依总控。审查或验收未通过不得进入依赖阶段；逐端回读、来源登记与实际同步状态记录不豁免，失败、中断与恢复依既有流程处理，未回读即未完成。生效真源为 Minis 本地文件：技能 `/var/minis/skills/<name>/SKILL.md`、常驻提示词正文 `/var/minis/memory/SOUL.md` 与 `minis-config` 的 `soul.body`（**以后者为生效值**；两者不一致时先判定当前生效版本，不自行挑一份覆盖其余）。逐处回读判等：常驻提示词 → Minis 文件与 `soul.body`、LobeHub agent 的 `systemRole`、仓库 `prompt/`；技能 → Minis 文件、LobeHub 的 `content`/`description`/`name`（三者独立，按支持入口分别更新）、仓库 `skills/`；子代理 → 仓库 `subagents/` 与两端助理配置。

脚本闭环与变更纪律依〈资源与触发〉所指资源执行。

**技能上游核对只认 GitHub 仓库**：判断某技能是否有上游更新，只比对上游 GitHub 仓库——默认分支 HEAD、目标文件末次提交与内容哈希，并与本地逐字 diff；不探测市场端点（skills.sh 等的搜索/下载接口），其可用性与返回码不纳入范围、不作来源依据，也不因端点异常改变结论。**来源例外（逐对象裁定、须登记）**：某对象的上游若由官方以**非仓库渠道**分发（已裁定：`luno-surge` 的官方 Agent Skill 只随 Surge Mac 应用包分发），则按**该对象来源登记里的官方分发渠道**核对——取源链接形态、包身份校验（bundle id／版本／build）与逐文件 sha256 判据写在该技能包内的来源登记文件（`luno-surge/references/SOURCE.md`），本条不列通用做法。例外只对该对象生效、须记入对象登记与当批条目，**不得外推**，也不得用同名第三方仓库（如 `SURGE-xyz/skills` 一类）冒充官方来源。

巡检输出按类别读：`内容不一致` 指本地↔仓库、`与平台不一致` 才是平台侧。同步技能文件用单文件内容复制；整目录 `cp -r` 曾把 mode 改成 755 污染 git（历史观察到的权限漂移，非通用行为；已漂移时按 `git ls-files -s` 恢复索引 mode）。

## 输出
列同步对象、三处落点核对结果、差异分类（本地↔仓库 / 与平台）、未覆盖项与回滚方式；未回读即未完成，未实测写明。
