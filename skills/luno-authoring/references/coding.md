# 共读资源（按原分支合并）

指针中的“分支”以 branch 锚点及 BEGIN/END 注释定界。沿用各分支原有触发和共同前置：完整读取命中的分支；原规则指定分节时，读取指定完整分节及共同前置，不加载未命中分支。同一文件的命中并集优先一次取齐，返回受限时分块补齐，不以截断内容作已加载。

分支内的“本文件”“本文”“本资源”均只指该分支，不把其他分支的接口事实、版本、能力或权限并入；“本技能”仍指原技能。主体、条件、例外、停止、恢复和许可边界保持原文，不因合并授予额外权限。跨技能先读目标技能入口及产品/业务入口；候选不改变现役规则。

# LUNO｜代码实施纪律

## 范围
跨语言的代码编写、修改、重构，以及代码审查时的实施侧核对。目标与产物量级、授权与提问、正式审查与分级、CI 与执行环境、规则仓库的测试准入，分别按 `luno-core`、`luno-core/references/review.md`〔分支 review〕、`luno-ops`、`luno-core/references/sync.md`〔分支 sync〕 原文，本文不复述。

## 动手前

验收先落为可判结果（命令、预期）；多步设检查点，收尾再跑完整检查，不以中途单点代整体。定位现有构建/测试/lint入口、生成物、目录命名、词表和ADR；沿用约定，缺项如实报，不猜。

行为改动按可独立验收的纵切片贯穿实际各层，做完可演示；不按库/接口/UI横向攒齐。跨大量调用点、无法分片通过的机械重构例外：新旧并存→分批迁移→核旧调用归零→删除旧形态，各批尽量可用；不能中途通过则明确最终集成点，不把中间态报通过。

## 改动

不为未出现用法投机泛化；单次使用通常不抽象，有当前需求、安全/正确性/成文规范依据才按收益与维护成本决定。重写看能否消除重复层，不看行数。

提交前逐处核diff：①能否追溯本次目标，不能则撤回（含格式/注释/重排），必要扩动说明关系；②本次引入的无引用import/变量/函数本批清理，既有死代码只报位置及可确认替代者，另获准且确定无用才删；③沿用周边风格，安全/正确性/成文规范优先。只有证据证明不可能的内部情形才按不可能处理；外部输入、鉴权、边界和故障仍按可达路径。

## 修正与重构

修bug先复现同一症状，优先自动用例修前失败、修后转绿，不以能跑通代替。难复现/反馈慢/链复杂时记诊断命令及一次真实非秘密结果，确认失败来自故障而非初始化/权限/邻近路径；反馈环以可重复、秒级、无人值守为目标，慢/人工说明限制和替代证据，随机故障在预算内记录命中率，不冒称确定。不可复现或无框架则报缺口及最小复现/日志/前后对比，不凭未验证假设直接改代码。

修后回跑原始未缩减场景；回归边界须触发并观察真实故障，多调用方/完整链不能以单调用方或过浅测试代替，无合适接缝报缺口。重构先有通过基线，改后同组检查通过；行为变化另作需求，不混入重构。

## 交付

交实际命令、结果、未验证及原因；文件存在或“应该没问题”不代证据。

# 软件国际化（i18n）

适用于代码、UI、locale、翻译键、复数、地区格式、RTL、回退和自动检查。优先复用项目现有的工具；只有验收确实需要、现有工具覆盖不了、并且有对应写入授权时，才新增最小的 i18n 检查脚本。报告实际检查的范围、跳过项和未覆盖的语言；工具通过不等于覆盖完整。

改动前先读项目的约定和 locale 文件，只改目标范围，保持键、变量、占位符和文件结构不变。检查要点：

- **硬编码**：已经调用 i18n 的文件也要查残留的硬编码文案，不整文件跳过。
- **键集**：按项目实际的组织方式（包括平铺的 `<locale>.json`，不假定形态），各语言的键对齐，没有缺键或多余键；同一个 locale 的文件里用户文案不混用语言（键、变量、占位符和专名除外）。
- **拼接与格式**：不拼接翻译串，占位符、复数和性数交给 ICU 或项目既有机制；日期和数字按目标 locale 格式化。
- **回退**：配置默认语言回退，并实测缺失翻译时的实际回退结果。
- **布局**：不假定译文长度；适用 RTL 时用逻辑属性，并实测布局和方向，不以用了逻辑属性代替实测。

改完运行可用的校验，报告修改的文件和键。
