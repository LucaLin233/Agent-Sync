## 安装和验收

`scripts/install.sh` 先把本包 `scripts/` 下的 `*.py`、`*.sh` 设为 755，再建立 `scripts/surge_cli.py` 到安装点的链接；安装是包外写入，须有目标授权。随后使用 `scripts/acceptance.sh --installed` 核链接实际指向；仅包内检查不证明 PATH 安装正确。

`--offline` 核语法和相对链接，不证明运行行为；`--controller` 会连接指定实例；`--network` 还会上传合成无秘密 Profile 并产生 DNS 请求。联机档有临时目录和输出写入，须分别满足工作根、清理、实例、网络和上传授权，未满足不运行。临时目录须按总控在单条命令内独占创建、退出清理并逐路径核验；脚本 trap 不保证 SIGKILL 后清理，未核实残留不得声称已清理。缺失变量只报告，不输出值、不换来源。当前设备未验证的能力如实标未实测。

## 打包、投递及恢复

只用 `scripts/package_release.py`，由 `tools/deploy_skill.py` 复用其收集和构包逻辑；ZIP 根不带顶层目录。保留符号链接/非常规条目拒绝、秘密扫描、候选摘要、源端漂移检测和资源完整清单门禁。禁止官方原件和 logo 进入包：打包器按 manifest 全部 build 的哈希并集拒绝已知官方整文件，所以换基线时只追加新 build。它只认整文件哈希，不能只靠文件缺失或拦截通过宣称许可审查完成。

部署只使用已合并且已独立验收的版本，按 `tools/sync-targets.json` 核目标实际身份和生效前态；投递仍走获准的私有 R2 / `lh skill install` 流程，预签名 URL 和临时凭据不得进入 argv、工具 JSON、回复、日志或文件，只经已核实的安全通道在授权源与目标之间传递；缺通道即停，不改成公开对象。变更后逐字节回读本次资源及变更元数据；安装成功、HTTP 200、CI 绿色不等于一致。

正文、来源或许可附件变化都会改变 Git blob、ZIP 及资源摘要；审批后重算并走候选摘要门禁，不为保住旧摘要回改正文或放宽断言。覆盖前备份本次目标的实际生效前态。并发漂移、部分失败或结果未知就停相关对象，不盲目重投或自动删除端上旧资源；列出已同步和未同步范围。恢复同样核授权及后续编辑，不能用旧备份强盖新变化。历史原件资源的移除须单列删除授权、恢复能力和平台限制；不声称新包安装必然删除旧资源。历史 prepare/apply 事务不自动迁移或清理；若曾在 state=applying 中断，停止新维护，先在独立授权下核旧事务的 backup、记录内容及原 mode，逐项恢复受影响的旧目标。新只读入口不能续跑旧事务，也不能把旧原件回写到自编候选或据此批准重新分发。
